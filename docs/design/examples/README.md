# HTML 源文本示例

运行时采用 HTML 节点与 SVG 连线，KaTeX 继续保留且允许局部 SVG。以下静态样例只记录源文本，没有绘制实现；拖动中连线是否实时跟随，必须在交互实现后检查，不能由静态样例推断。

这些文件对应[源文本技术草案](../source-text.md#技术草案)，用于检查格式与关系语义。样例直接展示源码、字段或表格数据，不包含导图渲染、卡片编辑、警告栏或保存实现。正式应用默认收起；展开为固定尺寸并冻结顶部标题区，正文滚动。收起时标题图片与笔记不渲染，卡片内容仍完整渲染并可滚动查看；静态样例不演示这些交互。

部分关系与内容样例有意省略节点坐标，读取时应走已有的缺失位置补齐规则；它们不是完整的规范化保存输出。删除前／后样例比较的是节点与边的语义变化，具体摆放与避让由带坐标的样例另行说明；缺少坐标不应在静态结构检查中被误报成不可读取的图。

[外壳 S1](../shell.md#s1-已确定的交付与离线使用)已确定正式图文件通过相对路径引用本地版本化公共资源，图中不内嵌编辑器或样式实现。现有样例继续作为源文本格式样例，不添加指向尚未生成资源包的链接；完整文档引用形式见[外壳中的目录示意](../shell.md#目录与引用草案)。静态样例不构成完整离线交付物，公共资源与浏览器行为需另行验证。

[外壳 S2](../shell.md#s2-已确定的文件操作)规定新建整张图从一个标题为“新节点”的节点开始，在内存编辑后首次手动保存才选位置；打开其他图替换当前页，不提供另存为。这里的空图样例仍合法，打开时不补节点；新建与摆放样例演示向图中新增节点，不代表整张新图的默认节点数量。

首版不提供按内容场景或关系的自动排版，但必须局部避让，禁止节点叠放。缺失坐标的半径 5 随机值及文件中的重叠位置仅是输入候选，不是可直接显示或保存的最终几何结果。静态源码只能验证结构；下文标注的几何结果以 240×160 图单位外框和允许边界接触为假设，不代表外观尺寸定稿或浏览器验证通过。

每个节点的出向关系列表是边的唯一源文本记录，不通过 HTML 嵌套建立业务关系，也不另外维护入向列表。图容器、节点和边都不使用 `data-type`，节点形态通过外观类名表达；边说明中的业务用词仅是文本，不构成分类或触发隐藏规则。

L6 统一使用通用节点；`round-rect`、`rect`、`diamond`、`parallelogram`、`circle`只表示外观，不限制卡片内容。L8 只接受 Markdown 图片与表格，区域可见性样例也只使用三个文本字段，不保留 `data-chart`、`data-slot` 或字段外 HTML 表格。现有静态样例只覆盖其中部分形态，不是工具栏或完整素材库实现；显式 `rect` 表示直角矩形，通用新建的默认形态为 `round-rect`。实际形态渲染和无损切换仍需后续浏览器验证。

A2 新增关系元素的路径外观类名 `bezier`、`orthogonal`、`straight`，既有样例不指定时按默认贝塞尔解释。三种外观不改变边的业务语义；说明仍是同一关系元素的完整纯文本，不增加说明框节点或位置字段。静态样例不证明绕行、交叉配色或说明框避让已实现。

连线交互规则见[逻辑设计](../logic.md#l1-已确定的连线交互)。现有静态样例可以不指定连接位置；新增的可选 `data-start`、`data-end` 格式和例子见[源文本草案](../source-text.md#连接点与端点改接)。连线两端的用户选点需要保存，路径中间形状不作为手动折点保存。

后续实现需验证以下连线操作，当前静态样例不提供这些事件处理：

| 操作 | 预期结果 |
| --- | --- |
| 点击连线入口，再点击 A、B 内部 | 创建 A → B，分别连接到最靠近两次点击的边缘点；不进入两节点的正文编辑 |
| 单击边，再按 Delete | 先显示焦点粗描边且说明框保持隐藏；Delete 删除整条边，保留两个端点节点及其其他关系 |
| 双击边，修改或清空说明 | 显示说明输入框并按 1024 个码点限长；清空说明仍保留边，退出编辑后隐藏框并保留有效文字 |
| 双击边后光标位于说明内，按 Delete | 删除整条边，不只删除说明中的字符 |
| 节点正文内有光标时按 Delete | 删除该节点及所有入边、出边，保留其他节点；退格或剪切仍是文本操作 |
| 将 A → B 的起点拖到 C | 同一边变为 C → B，条目从 A 的列表移到 C 的列表；保持 ID、说明与 B 端连接位置，节点坐标不变 |
| 将 A → B 的终点拖到 C | 同一边变为 A → C，保留 A 中的条目位置，只修改目标及该端连接位置 |
| 改接时在空白释放或取消手势 | 原关系保留，不留下无目标边，不新增节点 |
| 保存用户连接点及路径外观后重开或改变卡片尺寸 | 局部连接位置保留，显示点贴合节点边缘；不生成折点编辑数据，不重排节点 |

分类处理前的样例故意包含可处理的异常，不要求原始输入通过最终格式校验。读取时先按源文本顺序保留第一个同 ID 节点、删除副本及其自身出向边，再取消指向当前图中不存在节点的连线；对处理后的内容校验外观引用、标识、字段与端点，不校验边类别。无法处理的内容在警告栏提示并排除，最终边的两端都必须属于有效节点集，保存只输出有效数据。树、森林、回路、自环、多个入边、平行边、孤立节点和空图均按同一通用格式接受，不因内容场景触发树状拓扑限制。

删除前后样例展示主动删除与空标题自动删除共同调用的操作结果，原始样例文件本身均保持有效标题。验证自动删除时，在编辑控件草稿中清空 `topic` 标题并清空卡片文本、保留笔记，再执行失焦收尾；源文本标题不经过空值中间态，最终删除结果与主动删除相同。若仅清空标题草稿而卡片文本非空，则应交换草稿文本并保留节点及全部关系。

删除结果必须只移除目标及其全部入边、出边。剩余节点的标识、形态与内容，以及剩余边的标识、文本、端点与顺序保持不变；根节点删除后形成多个分支也可直接保存，不能自动挂接或补建根节点。

操作撤销由后续逻辑实现验收，静态样例不能证明历史功能已经存在：

| 操作 | 预期结果 |
| --- | --- |
| 主动删除 `topic`，再撤销 | 一次恢复 `topic` 与本次清理的全部 4 条关联边，标识、内容与顺序恢复到删除前，不只恢复节点 |
| 清空 `topic` 标题和卡片并失焦，之后连续撤销 | 节点自动删除不可撤销；`topic` 及此次清除的 4 条关联边不恢复，不能通过撤销先前文本或选择操作复活它 |
| 清空文字但尚未失焦触发删除时撤销 | 节点仍存在时允许恢复此前文字，空标题不进入有效源文本 |
| `topic` 自动删除后撤销无关节点 `note` 的编辑 | 仍能撤销 `note` 的有效操作，不因自动删除而清空全部历史 |
| 旧复合操作的恢复依赖已自动删除的端点 | 该记录不能原样回放；不恢复已自动删除对象、不产生悬空边或只恢复一半的复合操作 |
| 单独删除一条边，再撤销 | 恢复同一条边及连接位置，不新增或替换端点节点 |
| 拖拽节点或改接端点，再撤销 | 撤销整次手势，而非逐个指针移动事件；受影响的连线按恢复结果重新计算 |
| 载入分类修复或超长字段硬截断后检查历史 | 没有可撤销的自动修复条目，不能找回异常原文或超长尾部 |
| 手动保存或 Agent 改盘触发刷新后撤销 | 新会话没有上一会话历史，不恢复旧编辑或旧硬盘文件 |
| 用户主动展开卡片、平移或缩放后撤销 | 恢复对应页面状态，不修改节点坐标或为展示状态增加源文本字段 |
| 撤销后尝试重做或再次撤销 | 不提供重做入口，不经文本控件或依赖回放已撤销动作；再次撤销只处理更早的有效用户操作 |

新建示例使用“新节点”作为初始非空标题；`node-1` 改了标题，`node-2` 未修改默认标题也可以保存。空标题仅能暂时存在于控件草稿，不写入内存源文本。逻辑实现时需覆盖以下场景：

| 操作 | 预期结果 |
| --- | --- |
| 直接验证通用新增操作，`plan` 有焦点 | 创建标题为“新节点”的 `node-1` 并聚焦，追加默认贝塞尔边 `plan → node-1`；这是共用逻辑规则，不表示有焦点时点击形状按钮会新增 |
| `plan` 有编辑焦点时点击工具栏菱形 | 只将 `plan` 的形态改为菱形，节点数、ID、完整内容和边保持；不同时创建 `node-1` 或默认边 |
| 修改 `node-1` 标题，点击空白取消焦点，再新建 | 立即创建标题为“新节点”且获得焦点的 `node-2`，不连向任何节点；无需修改默认标题即可保存 |
| 将 `node-2` 拖到 `node-1` 的位置 | 禁止叠放；240×160 假设下，候选 (500,170) 向下避让为 (500,330)，边和源顺序不变 |
| 保存后重新读取，或调整视窗再读取 | 同尺寸无碰撞时恢复坐标，不重新应用新建间距；若真实外框变化造成碰撞则局部避让 |
| 用户清空新节点标题草稿和卡片后失焦或保存 | 删除新节点及新建时产生的入边，保留原节点；卡片非空则先与标题草稿交换，不把空标题写入源文本 |
| 通用新增操作的原焦点节点标题草稿和卡片都为空 | 原节点收尾删除，新节点仍以默认标题创建并获得焦点，定位沿用原外框快照；不留下指向已删除节点的关系 |
| 换形目标在编辑收尾时因空标题被删除 | 结束本次换形，不补建默认节点，不把同一形状点击改为新增 |

示例不再保存 `data-z`。未给出坐标的原始输入先生成半径 5 内的候选，再按实际外框避让；有坐标也须检查碰撞。无碰撞位置不动，负坐标允许，手动保存最终无碰撞坐标。

批量示例对应[逻辑 L3](../logic.md#l3-已确定的批量操作)。只支持批量移动、删除、复制；副本使用新 ID 并保留原标题和内容，不调用普通新建的默认标题与焦点连线规则。以下为源文本预期与后续交互验收场景，不表示静态文件具备多选或复制实现：

| 操作 | 预期结果 |
| --- | --- |
| 选择 A、B，整体移动 `(80, -40)` | 在示例尺寸下无碰撞，A 到 (180,60)、B 到 (500,120)，相对位移仍为 (320,60)，C、D 与边保持；若有碰撞须整组避让 |
| 批量删除 A、B | 清除两节点及 6 条关联边，仅保留 C、D 和 C→D；不重复删除 A、B 之间的边，不级联到 C |
| 批量复制 A、B | 240×160 假设下副本整组上移 160，node-1 为 (100,-60)，node-2 为 (420,0)，相对位移仍为 (320,60)，与原节点不重叠 |
| 复制内部边、平行边、自环和回路 | A→B 的两条边分别成为 node-1→node-2；B→A 变为 node-2→node-1，自环变为 node-1→node-1；均保留说明、所选路径外观和已有连接位置 |
| 复制 A→C 与 C→A | 新增 node-1→C、C→node-1，C 不复制；后一条必须位于原 C 的出向列表中，已有 C→D 保持原样 |
| 撤销任一批量操作 | 整次操作一次撤销；撤销复制清除两副本及全部 6 条副本边，包括 C 中新加的边，原有数据保持不变；不提供重做 |
| 进入或退出多选 | 批量选集与单对象焦点互斥；画面无节点叠放，普通点击只命中一个节点，不提供穿透选择 |

A1 已确定：源文本中的形态类名表示收起形状，五种形态展开后都显示为圆角矩形；展开与形状标识不存入文件。现有 HTML 是源文本样例，没有展开交互，不需要把样例的 `rect`、`diamond` 或 `circle` 改成 `round-rect`。

分类处理前后样例应按下列边界检查：

- 第一个 `topic` 及有效出边保留，后出现副本不因位置更合适而替换它，也不合并关系；后续碰撞单独处理。
- `plan-topic` 与 `leaf-topic` 继续指向第一个 `topic`，不能因为删除副本而把这两条入边一起删掉。
- 两条指向 `gone` 的剩余连线取消，不补建 `gone`，也不重接到其他节点。
- 在 240×160 假设下按源顺序接受位置：plan 保持 (0,0)，topic 从 (10,10) 避让到 (10,160)。leaf 随机候选 (1.2,-1.6) 满足半径 5，最终避让到 (1.2,-160)，不能再要求最终坐标满足半径 5。
- 不保存或比较叠放次序；修正后占用矩形无正面积交集，节点及边的源顺序保持。
- 同一已处理结果再次检查，不继续删除或重新随机定位；保存并重新打开后恢复处理结果。当前样例只表达输入与预期，不包含修复器实现。

Agent 写入限长由后续逻辑与候选命令行工具共同验收，静态样例不为此加入大段重复文本：

| 输入或操作 | 预期结果 |
| --- | --- |
| 三个字段长度恰好为 1024、1024、32768 | 不截断；只读检查报告均未超限 |
| 标题为 1023 个“甲”、一个 `😀`、一个“尾” | 原长 1025；载入保留前 1024 个码点，即保留完整 `😀`、去掉“尾”，不留下半个代理对 |
| HTML 文本使用 `&amp;`，或包含 CRLF 换行 | 按解码并归一化换行后的文本计数；实体 `&amp;` 计一个 `&`，CRLF 计一个 LF |
| 超限笔记的截断点位于公式或图片编码中 | 仍按前 32768 个码点硬截断，不向后保留完整标记，也不自行补全公式或图片数据 |
| 标题硬截断后仅剩空白 | 继续报告无效标题，不自动补默认标题或删除原节点 |
| 对含超限字段的原文件运行候选字数工具 | 报告截断前实际长度、上限与超出数量，检查不通过；文件保持不变，不触发坐标或重复节点修复 |
| 页面硬截断后再次渲染，再手动保存并重新打开 | 内存文本不继续变化；保存后重新读取保持截断结果，保存前磁盘文件不会被自动修正 |

带警告文件的前后样例保留 valid-a、valid-b 及有效正文，invalid-title 和相关边排除。当前示例尺寸下两有效节点无碰撞，原坐标保留；实际宿主尺寸不同时仍需局部避让。错误不阻断有效内容保存，已排除内容的警告在重开后消失，资源不可达提示可能继续存在。

保存结果不得带有隐藏的异常原文或警告节点，不要求维护源文补丁或恢复信息。有效笔记、合法的图片数据即使当前未渲染，也必须完整写出；“只保存有效部分”不是只导出当前屏幕可见部分。当前示例只表达保存前后的设计结果，不包含运行实现。
