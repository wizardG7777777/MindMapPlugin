# MindMap 架构设计

更新日期：2026-10-16。

状态：首版产品设计基线已齐备，源文本、外观、逻辑和外壳均有独立设计文档。P1–P7、L1–L4／L6–L8、A1–A4 与 S1–S4／S6 已确定，L5 撤掉、S5 暂不展开。首版只使用默认主题，无主题选择入口；HTML 节点与 SVG 连线、KaTeX、手动保存及强制刷新等规则保持。技术草案覆盖核心格式与流程，具体依赖版本、模块接入和宿主能力仍需实现验证，不视为已通过运行验收。

MindMap 按普通网页应用组织，采用 HTML 承载源文本、CSS 定义外观、TypeScript 实现逻辑，并由外壳将三者组织成可使用的页面。顶层架构固定为源文本、外观、逻辑、外壳四部分。

## 产品方向

项目面向用户和 Agent，追求轻便、易于分发和广泛的浏览器兼容性。用户在页面中查看和修改内容，Agent 通过 Skill 获得创建、理解和修改文档的指导，验证脚本用于检查生成与修改结果。

已确认的目标与边界：

- 文档以 HTML 为承载，所有文本信息保存在 HTML 中。
- 采用 HTML 节点内容、CSS 外观与 SVG 连线；允许运行时 SVG 及组件生成的 SVG，公式继续使用 KaTeX。拖动节点时关联连线必须持续实时跟随，不能仅在拖拽结束后更新；源文本仍保存内容与关系，不保存派生绘制结果。
- 图由节点与有向边组成，取消基础关系类型，节点之间只由实际存在的边建立连接。树和森林是其特例，不按内容场景强制无环、单父、连通性或根节点数量。所有图允许保存回路、多个入边、平行边、孤立节点和空图。不提供子树或分组折叠，保留单个卡片展开笔记。
- 主动删除和空标题自动删除共用规则：移除目标节点及全部入边、出边，保留其他节点和关系；不自动提升子节点、重接连线或改变孤儿节点的归属。
- 连线默认贝塞尔，也可创建直角折线或直线。曲线与折线自动绕开无关节点，直线允许被节点遮挡；交叉边使用不同颜色。说明框属于边，仅双击编辑时显示，退出编辑隐藏；显示时全文扩张，中心默认在路径中部，通常避让节点和其他可见说明框，隐藏框不参与避让。直线空间不足时说明框优先级低于节点，可被节点遮挡，当前暂不解决该极端情况；隐藏或被遮挡不影响保存、计数和查找。
- 工具栏形状按钮有节点编辑焦点时换形、无节点焦点时新增；手动建边必须先选线工具，再依次选起终点并投影到最近边缘点。既有自动连线默认贝塞尔，复制仍保留全部关联边及原外观。单击边选中、双击编辑说明，端点拖拽改接规则保持，暂不提供折点编辑。
- 对象焦点至多指向一个节点或一条边。节点或边有焦点时，Delete 删除整个对象，即使文本控件内有光标；边单击选中后即可删除，节点删除清理全部关联边，单独删除边保留端点节点。
- 提供用户操作级撤销，独立自动操作不可撤销。用户主动删除节点与关联边视为一次完整操作，撤销时一起恢复；空标题失焦自动删除则不恢复节点和关联边，也不能通过更早的编辑历史间接恢复。任何刷新清空撤销历史，包括手动保存引发的刷新，不提供跨刷新文件回滚；只提供撤销，不提供重做。
- S4 规定撤销仅用 Ctrl+Z／Cmd+Z；复制、删除同样只提供快捷键，Delete 保持对象级删除，不设相应按钮或菜单。新建图、打开其他图、保存始终位于左侧工具栏最上方；缩放滑块和比例、回原点、查找入口放在右上角，与警告栏同区。查找仅通过上／下箭头定位上一／下一对象，不点击结果列表或输入即跳转。
- 普通新建先按焦点右方／下方的视窗 5% 间距或视窗中心生成候选。完全禁止节点叠放，冲突时移至最近空位，允许局部移动其他节点；不提供置顶、置底或逐层调整。
- 通用新增操作立即创建标题为“新节点”的节点并聚焦；有原焦点时自动建立默认贝塞尔边，无原焦点时不连线；原节点收尾删除时不保留该边。形状按钮有节点焦点时只执行换形，不调用这套新增流程；换形目标收尾删除时不补建节点。复制保留原标题与内容，源文本有效标题始终非空。
- 单节点拖拽指定期望位置，批量移动保持选集内部相对位置；发生碰撞时自动局部避让，必要时调整邻居。边、正文与源顺序不变，手动保存最终坐标，不保存叠放层级。
- L3 只支持批量移动、批量删除、批量复制，不提供其他批量修改。批量删除沿用单节点删除规则，统一清理全部关联边；复制所有关联边，选中端点改为副本、未选端点保留原节点，原节点和原边继续保留。每次批量操作整体撤销，不提供重做。
- 批量节点选集与单对象编辑焦点互斥，不写入源文本；批量模式下 Delete 删除选集，单对象模式沿用已有删除规则。
- A3 统一焦点外观为粗描边，默认背景下为蓝色。鼠标框选只选节点，全部选中节点有描边但不同时编辑文字；边单击选中，双击才显示说明输入。查找仅突出当前定位对象，不改变编辑焦点；无悬停反馈或额外操作过程提示。
- A4 默认画布为浅灰点阵；画布内所有元素等比缩放，不保证最小可辨识尺寸。工具栏、查找工具与警告栏使用当前主题配色，默认白底黑边；点阵不产生吸附或图对象，配色不增加独立文档字段。
- S6 明确首版仅使用默认主题，直接加载，不提供主题选择或切换入口；默认主题覆盖全部图与工具区域，五种节点形状、三种线型与交叉边异色不受影响。未来多主题不作为本期设计或验收任务。
- 重新打开或刷新文件时，所有卡片默认收起。鼠标长按卡片 1 秒或点击右上方圆形按钮后，所有形态统一展开为固定尺寸圆角矩形，标识当前收起形状；标题区冻结置顶，卡片内容与笔记在下方滚动，卡片内容不冻结。收起时笔记全部隐藏，标题图片不渲染，卡片内容中的图片完整渲染；可见表示能直接或通过滚动查看。
- 打开或刷新后自动平移与缩放，使所有有效节点可见；允许手动调节比例，提供回原点，不提供手动显示全部或恢复 100%。视野与查找状态不写入源文本。
- 查找只提供节点、边两种筛选，无筛选时检索所有有效文本，包括收起内容；节点定位使视窗中心对准节点中心，命中不自动展开。编辑焦点对象持续保持可见，必要时自动平移视野。
- 用户文本在输入阶段限长：普通输入超限拒绝，粘贴超限截断。不另设超限禁止保存流程；Agent 超长写入在载入时硬截断。标题、卡片文本与连线说明各限 1024 个 Unicode 码点，笔记限 32768；连线说明仅纯文本，不解析 Markdown／LaTeX，UTF-8 仍为文件编码。
- 标题、卡片文本和笔记统一支持 Markdown，以及内联和块级公式。图片推荐使用链接，也允许内嵌；图片无法加载时仅在预览位置显示固定警告，保留原始引用，不影响其他内容或正常保存。
- 载入时按规则去重、取消无目标边、截断超限文本，缺失坐标在原点半径 5 内生成候选；测量有效节点后局部避让，最终可以超出该半径。重叠不导致内容删除或禁止保存，不再补齐层叠字段。
- 无法自动处理的错误集中在网页右上方警告栏警告，有效部分继续展示、编辑；手动保存只写出有效内容，异常原文及相关无效连线不保留。合法的隐藏笔记和媒体仍完整保存。
- 当前内容范围按 L8 收缩：图片与 Excel 式行列表格仅用 Markdown；不增加表格额外能力、手绘、分区边界、线框或模板。时序先用有向边表达；早期飞书能力覆盖设想不作为当前实现清单。
- 首版支持手动摆放与连线，不提供全图或局部自动排版。先把手动创作、编辑、保存和恢复做完整并验证可用，再针对具体布局场景逐项设计自动排版，不恢复图类型字段；自动排版不作为所有图共用的首版能力。
- 保留新建定位、缺失坐标补齐、连线路径计算及Markdown 表格预览所需的排版，围绕预期的 10–200 个节点创作场景实现交互和性能目标。
- 外观使用 CSS，运行逻辑与验证脚本使用 TypeScript；浏览器执行由 TypeScript 编译得到的 JavaScript。
- S1 已确定图 HTML 只保留源文本、必要文档结构与资源引用；外观、逻辑和外壳连同依赖作为按版本管理的本地公共资源，多张图通过相对路径共用。资源准备好后无需安装插件即可离线使用，不依赖联网缓存；首次交付需同时提供对应资源，单个图 HTML 不自带完整编辑器。插件侧重点仍是 Skill 和验证脚本。
- S2 提供新建图和打开其他图，不提供另存为。新图仅含一个标题为“新节点”的节点，卡片文本、笔记为空且没有边；先在内存编辑，首次手动保存时选择文件位置。打开其他图替换当前页中的图，后续保存写回当前文件。新图起始节点不改变允许空图的规则；S5 的文件标识、未保存标记与主动离开提醒暂不展开，不新增相应的自定义流程。
- 不提供多用户协作，不承诺用户与多个 Agent 同时修改时的自动协调或合并。

所有新建图统一为有向图，不设置图类型或业务节点类型。工具栏提供圆角矩形、直角矩形、菱形、平行四边形和圆形五种启动形态，允许混用及自由切换，保留卡片全部内容。相关规则与当前内容范围见[通用图与内容场景](diagram-types.md)；L8 已排除分区与边界展示，宿主兼容范围和具体性能指标仍待验证。

项目预计在用户要求下辅助创作 10–200 个节点的图。1000 个及以上节点不纳入当前支持目标或性能验收范围；1000 个节点仅作为理解潜在开销的假想情形，不据此增加开发要求。10–200 是预期使用规模，本轮不据此新增节点数硬性校验上限。

先完成产品功能，再在预期使用规模内分析性能并针对实际瓶颈优化。当前只记录可能造成卡顿的原因，不将专门的大规模节点优化作为架构定稿或功能开发的前置条件。

## 主要原则

用户编辑、Agent 编辑及磁盘变更遵循以下原则：

1. **用户编辑先存于内存，手动保存后才写回硬盘。** 文本、节点增删、移动和样式等编辑以及必要局部避让先进入内存；保存写出有效内容和最终无重叠坐标，不保存层叠，不因摆放不整齐自动排版。独立自动避让改变的坐标也需手动保存，不自动追写。
2. **Agent 直接编辑硬盘上的源文本。** Agent 直接修改 HTML 图文件中的源文本层，其修改对象是硬盘文件。
3. **磁盘文件发生任何更改，强制刷新并丢弃未保存内容。** 当前打开的图文件在硬盘上发生任何更改，都会强制触发打开该图的页面刷新，重新加载硬盘上的最新内容。刷新时，用户尚未保存的全部内存编辑直接丢失，不自动保存、保留或合并。

磁盘变更的来源不限于 Agent，也包括用户手动保存以及其他工具对该图文件的修改。强制刷新不因存在未保存编辑而推迟，也不等待用户确认。

用户操作的撤销只作用于当前加载会话的内存文档或页面状态，不自动写盘。刷新同时清空撤销历史，不能用历史记录恢复此前丢弃的编辑；保存成功并刷新后，也不能撤销上一会话的操作。

以上是已确定的产品行为。初期文件写入采用 File System Access API，以同一套 TypeScript 保存逻辑覆盖支持该接口且允许文件授权的桌面 Chromium 环境，由浏览器处理操作系统差异。先验证 Chrome 和 Codex 内置浏览器，再根据更多 Agent 应用的实际验证结果补充适配，不预先按操作系统或应用分别设计多套保存方案。

具体文件句柄、授权与写入流程见[源文本技术草案](source-text.md#手动保存与文件写入方案)。alpha.2 已实现现有图的最小文件流程，并在本机 Chrome、Codex 中分别验证真实保存、外部改盘刷新及草稿/历史清空，证据见[验收记录](../../verification/html-milestone/README.md)。完整文件操作和更多宿主仍需后续验证，不能由文件写入接口的存在推定监听或所有兼容能力均已具备。

## 四部分职责

| 部分 | 职责 | 主要内容 |
| --- | --- | --- |
| 源文本 | 记录内容、属性、边、坐标，以及节点形态和外观选择 | 文本、笔记、Markdown 图片与表格、边与连接位置、节点最终坐标；不保存叠放顺序 |
| 外观 | 提供节点和图可以使用的样式 | CSS 样式定义，包括形状、颜色、字体、尺寸及图的整体视觉表现 |
| 逻辑 | 执行所有功能行为与自动化处理 | 编辑、手动摆放、连线路径计算、增删后的显示更新、校验和保存；首版不自动重排节点 |
| 外壳 | 将源文本、外观和逻辑组织成可使用的应用 | 页面入口、资源加载、功能接入、界面组织与运行调度 |

这些划分描述职责，不要求拆成四个独立软件包或服务。解析、保存、校验等功能归入四部分之内，不另设顶层架构层。

## 源文本

源文本保存所有文本信息，并明确描述节点及图的抽象信息，包括：

- 节点自身的定义。
- 节点标题、节点卡片文本与节点笔记文本。
- 节点属性。
- 节点之间的关系。
- 节点在图中的最终无碰撞位置。
- 节点的几何形态引用。
- 图与节点使用的样式引用。

节点属性描述节点的含义与特征，样式引用指定节点采用哪种外观。两者分别表达，不通过外观反推节点含义。

例如，用户可以在卡片中写判断条件并选择菱形外观，但程序不据此赋予“判断节点”业务类型。内容与属性属于源文本，具体 CSS 属于外观；切换为圆形或矩形时保留全部内容、属性和关系。

节点形态和图所使用的样式由源文本给出，不保存图类型或业务节点类型。节点是承载内容的最小用户操作单元，边是可以独立操作的连接对象；卡片的内容按标题、卡片正文、笔记组织，图片也按所属部分继承可见性。展开时标题区固定在顶部，卡片正文及笔记在下方滚动；收起时笔记与标题图片不渲染。边记录起点、终点、可选说明和用户选择的连接位置，不记录类型，允许独立节点、多个入边、回路及自环。

所有节点在源文本中平级列出，源节点声明自己的出向边；HTML 嵌套、节点位置、节点形态都不自动定义父子或业务关系。方向和可选说明表达连接的具体含义，不从说明关键词或外观重新推导内置类别。图、节点和边均不设置业务类型选择入口；工具栏选择的是节点几何形态或 A2 的连线路径外观。

节点坐标独立于源顺序记录，不再定义层叠字段。保存避让后的有效坐标，重开按当前尺寸检查，无碰撞保持原位，有碰撞局部修正；卡片展开状态不保存，源文本的形态引用仍表示收起形状。

树形图使用同样的节点与边表达，不另设树专属数据结构。源文本校验保留字段、标识、外观引用、边端点及文本内容约定，不校验边类别；布局适用性不决定文件是否有效，也不能为满足某种布局而自动删除、反转或补建边。

删除后留下的孤儿节点、离散节点和多个层级根均可直接保存，插件不自动改变它们的关系。最后一个节点删除后保留有效的空图，不创建占位根节点；样式和其他文档信息仍保存。删除清理关系时不得保留指向已删除对象的无效引用，合法的孤立节点与无效引用分别校验。

读取时重复 ID 仅保留第一个节点及其自身出边，其他副本删除；无目标边清理不误伤有效节点。缺失坐标先生成候选，再对有效节点局部避让；坐标修正不改变内容与边，也不恢复丢失正文。

不提供子树或分组折叠。卡片展开只存在于内存，重新打开或刷新时全部收起，隐藏内容仍完整保存；坐标恢复后按当前外框避让，不恢复层叠或按空隙自动收拢。

[源文本设计草案](source-text.md) 分开记录产品设计与技术草案，负责节点内容、展示语义、有向边及 HTML 表达方式。[通用图、节点形态与内容场景](diagram-types.md) 记录几何形态与内容目标，不建立业务类型清单。

HTML 标签与属性可以随产品需要扩充。字段名称、编码和校验方式由产品内容推导，作为技术草案逐项编写；新增标签不单独视为顶层架构问题，也不要求产品设计先穷举所有字段。

需要用户确认的是内容含义和操作结果；当前[源文本 P1–P7](source-text.md#需要用户确定的产品问题)、[逻辑规则](logic.md#未确定的产品问题)及[外壳产品清单](shell.md#未确定的产品问题)均已按首版范围收敛。具体接口、参数、实现与验证由开发方补齐；只有新增产品取舍或实测无法满足已定要求时再进入产品讨论。

文本编辑与预览沿用原生多行 `textarea`、`react-markdown`、`remark-gfm`、`remark-math` 与 `rehype-katex`，底层公式渲染继续使用 KaTeX，允许其局部 SVG 符号。内联与块级 LaTeX 的产品支持不变。三个字段共用 Markdown、表格、图片及内联／块级公式能力；图片失败提示由 TypeScript 逻辑补齐，常量文本见源文本技术草案。画布交互、内容渲染和连线路径依赖另行选型，首版不为自动排版引入布局引擎。

## 外观

外观对应网页应用中的 CSS，集中定义所有可用的节点样式和图样式。节点外观形状与图的整体视觉表现都在这一部分定义，源文本通过引用选择使用的外观。

[外观设计草案](appearance.md)分别记录产品方向与技术接入。已确认以简洁为基准，参考用户提供的卡片样式；A1–A4 已记录，S6 明确首版仅使用默认主题。对照稿中的具体尺寸与样式参数仍是待验证的技术初值。样式与必要字体、图标按 S1 放入本地公共资源，图 HTML 只保存形态、样式引用和必要资源链接。

外观定义视觉表现；新建定位、拖拽坐标换算、尺寸测量、连线路径及 Markdown 表格内部排版归逻辑部分。样式会影响元素尺寸，逻辑据此更新相关路径与内容显示，首版不根据关系重新计算已有节点坐标。

节点不能部分或完全重叠。外观提供实际占用尺寸，逻辑检测碰撞并自动局部避让，不能靠绘制层次掩盖冲突；选中描边和界面浮层属于内部呈现，不是文档层级功能。

外观提供所有形态共用的固定圆角矩形展开外框、冻结置顶的标题区、正文滚动区和右上方圆形按钮；标题栏显示收起形状图标与名称。具体宽高由外观实现确定，展开只有一档尺寸，编辑和预览共用；标题不随正文滚动，卡片正文不冻结。收起状态也要允许滚动访问全部卡片内容，不将溢出部分永久裁掉。

源文本已采用原生 `class` 引用收起形态和样式。A1 已确定收起时各形态使用水平阅读区域、展开统一为圆角矩形，并且只读标识收起形状。A2 的连线与说明框规则、A3 的统一焦点描边及说明框仅编辑时显示、A4 的浅灰点阵、等比缩放和主题工具配色均已记录；A1–A4 当前没有剩余产品待定项，技术样式参数由开发方补齐并验证。

## 逻辑

逻辑使用 TypeScript 实现，承担所有功能操作，以及适合由程序确定性完成的处理。[逻辑设计草案](logic.md)分别记录已确认的产品规则、未确定的产品问题和技术草案。已明确包含：

- 单节点拖拽和批量移动先生成候选，再在保持批量相对位置的前提下局部避让；只为实际碰撞调整目标或邻居，不改写边或源顺序。
- 按 Unicode 码点限制页面文本输入，拒绝超限的普通新增，按剩余容量截断粘贴内容；统一处理选区替换与输入法提交，使已接受的内存源文本始终满足长度上限。
- 对 Agent 直接写入的超限字段，在图文件载入时按各字段上限硬截断，保留处理记录；不实时拦截写盘，不自动把内存处理结果追写回文件。
- 统一渲染三个文本字段的 Markdown、图片、内联与块级公式；图片加载失败只更新局部预览，不改写图片引用或将警告当作源文本。
- 按标题、卡片内容、笔记的归属和展开状态控制图片渲染；连线说明单独按纯文本处理并限长。
- 首版保留用户与 Agent 指定的节点坐标，不提供全图或局部自动排版；卡片内部排版和 Markdown 表格预览正常执行。
- 以“新节点”为默认标题立即创建节点，按旧焦点建立原节点到新节点的有向边，再将焦点交给新节点；旧节点收尾删除时不创建无效关系。
- 根据新建焦点与视窗快照计算 5% 或居中候选，再按实际外框避让；无碰撞候选保持，有冲突以禁止叠放为准。
- 保证展示和提交状态无节点重叠，不提供层级命令、叠放字段或遮挡穿透选择。
- 序列化最终节点坐标，同尺寸无碰撞时重开保持；有新碰撞只局部修正，不按内容场景或关系整图排版。
- 持续拖动时同步更新节点与受影响的 SVG 连线，不等待鼠标松开；使用一致坐标与视野变换，公式内容未变时复用已有排版。
- 节点增加或删除之后的画面与连线显示更新；仅碰撞时局部避让，删除不自动重组剩余节点的关系或收拢空隙。
- 卡片默认收起，保留长按 1 秒、圆形按钮与内部滚动；外框变化先测量与局部避让，再更新路径。用户动作引发的连带位移整体撤销，独立自动避让不入历史；不实现子树或分组折叠。
- 工具栏形状按钮按点击前节点焦点分发：有焦点时换形并保留原节点、内容和边，无节点焦点时创建对应形态；用户联动避让整体可撤销，不执行批量换形。
- 有向边的增删与修改，以及标识、端点、说明和连接位置校验；无边类型枚举，不执行树专属拓扑限制。
- 工具栏依次点选建边，按鼠标最近边缘点确定连接位置；单击选边、双击编辑说明、拖动端点改接。连接位置随保存保留，路由中间形状仍由程序计算，创建时的路径外观选择不影响该约束，不提供手动折点编辑。
- 统一节点和边的对象焦点与 Delete 删除分发；建边取点、节点拖拽和边端点拖拽分开处理，Delete 不下放成字符删除。维护批量节点选集、当前查找标记和边说明编辑状态，向外观投影统一描边，不把共享外观误当作相同编辑操作。
- 载入时执行已定分类修复，缺失坐标只是初始候选，有效节点与外框确定后局部避让；不对未知正文、字段或内容结构猜测补全。
- 构建用于编辑、渲染和保存的有效数据模型，无法处理的内容排除并输出右上方警告；从有效模型整体生成图文件，不维护异常原文、源文范围回写或局部补丁。
- 规划供 Agent 使用的只读字数检查命令行工具，与页面复用同一套 TypeScript 字段识别、码点计数和长度常量；报告原始长度与超出数量，不先修复或截断再检查。当前只记录职责，工具尚未实现。
- 统一执行主动删除和空标题自动删除，清除目标的全部入边、出边，保留其余内容；接受空图、树、森林、回路与孤立节点。
- 批量删除对关联边集合按 ID 去重清理；批量复制使用操作前快照，为副本节点和边分配新 ID，重映射选中端点，正确追加外部入边，保持所有原边。
- 区分控件标题草稿与已接受的源文本，防止空标题进入源文本；收尾根据草稿交换标题与卡片文本或删除节点，不忽略用户清空标题的编辑意图。
- 载入后按有效节点的实际范围自动适配视野；维护节点／边文本查找、命中定位、回原点和编辑焦点跟随，不通过浏览操作改写坐标或保存视野。
- 根据内容、关系和形态样式执行相应的更新；切换形态不转换或筛除任何有效内容。

已确定由程序完成的操作归入逻辑部分，例如坐标换算、连线路径、文本限长和校验。用户通过拖拽摆放节点，Agent 可以直接在源文本中指定坐标、内容和关系；首版不推断它们期望的整体布局。

解析、修改、保存、用户操作撤销和结构校验在逻辑内部设计。撤销记录包含用户动作的必要联动结果，自动载入修复与派生显示不作为独立历史项；空标题自动删除清除自身恢复路径和会复活相关对象的旧历史，但不清空无关的有效记录。撤销合法的主动删除内容不等于保留异常原文。L2 已确定不提供重做，应用不维护重做历史或入口。编辑、保存与刷新遵循[主要原则](#主要原则)，具体实现与接口由开发方补齐，不沿用旧版 CLI 的实现契约。

所有图都禁止叠放。单节点或刚性选集移动可引起局部邻居避让，但不改变内容和边；端点改接仍只改变关系。首版不提供按内容场景或关系的自动排版，局部碰撞修正作为独立几何约束必须执行。

## 外壳

外壳负责将源文本、外观和逻辑装配起来，形成用户与 Agent 可以使用的页面。所有组织这三个部分的代码归入外壳。

[外壳设计草案](shell.md)分别记录产品设计与技术草案。S1 已确定：图文件保存有效源文本、必要格式信息及资源引用；外观、逻辑、外壳和依赖放在明确版本的本地公共资源目录，通过相对路径加载。普通图编辑不修改公共资源，普通保存不内嵌运行代码或生成的工具界面；新旧资源版本可以并存，不在打开或保存时自动升级。

外壳负责功能入口与调用时机，具体操作由逻辑执行。左侧竖向浮置工具栏顶端固定新建图、打开其他图、保存，下方提供五种形状和线工具；形状按钮有节点焦点时换形、无节点焦点时新增，手动建边先选择线工具。撤销只用 Ctrl+Z／Cmd+Z，复制与删除也只用快捷键。缩放滑块和比例、回原点、查找入口位于右上角，与警告栏同区；不提供手动显示全部或恢复 100%。工具外形沿用参考截图，外壳向逻辑提供扣除可见工具覆盖后的可用画布范围，用于适配、定位和跟随。

外壳向预览逻辑提供原图文件的资源基址，使相对图片链接按图文件所在位置解析；不强制将链接图片打包进 HTML。宿主无法读取某资源时，逻辑采用已定的固定警告。

外壳在网页右上方组织常驻的横向警告栏，展示逻辑返回的位置与原因，无警告时显示空状态；警告栏不可关闭，与可编辑图共存，不因局部错误替换整张图或禁用有效内容保存。其下方是横向查找框，默认关闭、按需打开并提供关闭按钮，仍只按节点／边筛选；关闭查找不影响警告栏。保存后从新文件重新计算警告，已排除内容的错误不继续保留。

工具栏、查找工具与警告栏使用同一当前主题提供的各自配色，默认均为白底黑边。左侧工具栏常驻且不可收起；三个工具区域浮置覆盖画布局部，不形成全高侧栏或横贯页面的实心顶部面板，也不加入图坐标的平移缩放。画布中的节点、文字、连线及图内控件统一等比缩放，不维持最低可辨识尺寸。可见工具的遮挡范围参与适配、定位和焦点跟随计算，不移动图中节点，不改变 A3 无悬停反馈规则。

S2 的文件操作已确定：新建单节点图先保存在内存，首次手动保存才选址，打开其他图同页替换，不提供另存为。外壳在切换时同步当前文档、文件句柄、资源基址、资源版本和变更检测对象，不能把新图写回旧文件。S3、S4 的布局、显隐与入口分发已确定，S5 暂不展开，S6 不提供主题选择入口。具体构建和宿主接入由技术草案补齐，本地资源就绪不代表文件写回或变化检测已经可用。

## 配合方式

以用户拖拽单个节点为例，四部分的职责如下：

1. 外壳接入页面交互，并调用逻辑处理拖拽操作。
2. 逻辑将指针位移换算为候选图坐标，测量并局部避让，得到无碰撞结果。
3. 逻辑原子更新目标及必要邻居的位置与路径，保留边与源顺序；用户动作及连带位移计为一个撤销记录。
4. 页面使用源文本所引用的 CSS 样式呈现更新结果。

上述结果先进入内存，手动保存时写出有效内容和最终坐标；任何磁盘变化强制刷新，重新读取并按当前尺寸避让。独立自动避让不入历史、也不自动写盘。位置字段与文件封装约定见源文本草案。
