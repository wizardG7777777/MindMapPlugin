# 源文本设计草案

更新日期：2026-10-16。

本设计遵循[四部分架构](architecture.md)。产品设计草案规定节点包含什么、如何展示，以及节点之间的关系；技术草案据此定义 HTML 表达与处理方式。需要用户决定的内容集中在产品问题清单；字段名称、格式编码、事件接入、校验与依赖配置由开发方补齐，不逐项作为用户确认事项。技术草案描述完整目标，当前仅文件流程里程碑完成实现与本机双宿主验收，范围见[工程记录](../../app/README.md)。

## 产品设计草案

### 图文件与公共资源的边界

按[外壳 S1](shell.md#s1-已确定的交付与离线使用)，每张图的 HTML 只保留用于描述图的源文本、必要文档结构与资源引用。节点、边、正文、坐标、连接位置和已有形态／样式引用继续保存；具体 CSS、运行程序、依赖、字体与用户操作界面不内嵌到图文件。

外观、逻辑和外壳作为按版本管理的本地公共资源，由图通过相对路径加载，资源就绪后支持离线使用且无需安装插件。普通编辑和保存保持所引用版本，不复制程序或渲染结果到源文本；Agent 可直接修改图 HTML。外链及正文内嵌图片沿用原有规则，不把运行资源的外置要求误用于删除用户内容。

[外壳 S2](shell.md#s2-已确定的文件操作)提供新建图和打开其他图，不提供另存为。新建图在内存中包含恰好一个默认标题为“新节点”的节点，卡片文本和笔记为空、没有边；首次手动保存时选择位置。打开其他图替换当前页面中的图。新图的初始节点数不构成格式约束，已有空图及删除最后一个节点后的空图仍可保存，不自动补节点。

### 已确认的节点定义

节点是图中承载内容的最小用户操作单元。节点标题、节点卡片文本和节点笔记文本共同属于一个节点，不作为三个独立的图节点。边作为连接对象可以独立选中、编辑说明、改接端点和删除。

| 内容 | 用途 | 显示时机 |
| --- | --- | --- |
| 节点标题 | 标识节点的主题 | 两种形态下均可查看；展开时标题区固定在顶部；收起时不渲染标题区中的图片 |
| 节点卡片文本 | 展示节点在卡片中的内容 | 两种形态下均可完整查看，内容过长时通过滚动访问；不冻结位置 |
| 节点笔记文本 | 承载节点的补充内容 | 展开节点后额外显示 |

卡片收起时显示标题与卡片内容，隐藏全部笔记；标题中的图片在收起时不渲染。卡片展开时一律显示为统一固定尺寸的圆角矩形，标题区冻结在顶部，下方按卡片内容、笔记的顺序滚动；卡片内容不冻结。可见指用户能够直接或通过滚动查看内容，不要求所有内容同时出现在视野中。

### 卡片展开与节点可见性

卡片收起状态参考下图。收起的卡片仍可包含较多信息，标题文字和卡片正文继续显示；笔记全部隐藏，标题中的图片也不渲染。图中的配色、边框等具体视觉形式由外观设计定义。

默认外观的参考原则、样式参数与技术验证集中在[外观设计草案](appearance.md)。首版仅使用默认主题，保持简洁的方向已确认，对照稿尺寸仍是待验证的技术初值；本文件继续只规定内容与保存语义。

![用户提供的卡片收起状态参考：标题区与包含较多信息的正文区](assets/card-collapsed-reference.png)

| 展示状态 | 节点卡片的内容与尺寸 |
| --- | --- |
| 卡片收起 | 使用保存的收起形状，标题文字与卡片内容在水平阅读区滚动查看；标题图片不渲染，笔记全部隐藏；重新打开或刷新时全部采用此状态 |
| 卡片展开 | 统一固定宽高的圆角矩形；标题区置顶，并显示收起形状图标与名称；卡片内容与笔记在下方滚动，标题图片恢复渲染 |

收起形态的具体阅读区域与展开布局见[A1 外观规则](appearance.md#a1-已确定的节点阅读区域)。展开不改写原形态或创建另一节点；标题栏的形状图标与名称只是只读标识。展开时主动切换形态，改变的是收起形状，展开外框保持圆角矩形。

展开有两种入口：鼠标在卡片上持续长按 **1 秒**，或点击卡片右上方的**圆形展开按钮**。普通单击卡片仍只获得编辑焦点，不自动展开。

展开状态只有一档固定尺寸，不按笔记长度自动增高，不提供多档展开尺寸或自由拉伸。固定宽高的具体数值由外观部分定义；编辑和预览使用同一展开外框，标题固定置顶，卡片内容及长笔记在下方滚动。收起状态的卡片内容同样不能因放不下而丢弃、截成摘要或永久隐藏，应允许滚动访问。

展开预览中，笔记为空时省略分隔线、标签与空白分区；进入展开编辑时仍提供笔记输入入口。空 `div.notes` 始终保留，界面省略不等于删除字段。

可见性统一按“标题—卡片内容—卡片笔记”的归属判断，与节点是哪一种内容场景无关：

| 内容所属部分 | 收起状态 | 展开状态 |
| --- | --- | --- |
| 标题中的普通文本、公式等内容 | 可见，可滚动访问超出部分 | 位于冻结的标题区，可查看完整内容 |
| 标题中的图片 | 不渲染、不可见，不以占位图替代 | 在标题区渲染 |
| 卡片内容中的文本、图片、Markdown 表格 | 完整渲染，可通过滚动查看 | 完整渲染，随正文滚动，不冻结 |
| 卡片笔记中的所有内容 | 不可见，不渲染笔记预览 | 渲染并随正文滚动 |

图片与表格仅通过三个字段中的 Markdown 源码表达，继承所在字段的可见性；它们不是独立业务节点，也没有字段外的内容存储区域。隐藏只影响当前预览，源文本与资源引用仍保留。

保留卡片自身的收起与展开，用于切换笔记及标题图片的显示。不提供子树折叠，也不通过折叠分组或沿关系隐藏一组节点；这一规则适用于所有图。收起一张卡片不会隐藏其他节点或改变关系。

卡片展开不改变已经确定的编辑焦点与源码／预览切换规则。笔记在卡片收起时仍完整保留，读取、修改、校验和保存均包含其内容。

卡片展开状态仅在当前页面内存中保留，不随手动保存写入文件。保存包含完整内容、属性、收起形态及样式引用、边和避让后的节点坐标，不保存节点叠放层级。重新打开或刷新时全部收起，恢复已有坐标并按当前尺寸检查碰撞；无碰撞时不移动，有碰撞时局部避让。这也适用于手动保存或 Agent 改盘引发的刷新。

卡片展开、收起及尺寸变化由逻辑更新测量和连线路径；有碰撞时执行局部避让，允许调整受影响节点位置。外观定义视觉尺寸，本文件记录内容与坐标保存要求。

### 文本内容规则

| 内容 | 是否允许为空 | 最大长度 |
| --- | --- | --- |
| 节点标题 | 不允许为空 | 1K，即 1024 个 Unicode 码点 |
| 节点卡片文本 | 允许为空 | 1K，即 1024 个 Unicode 码点 |
| 节点笔记文本 | 允许为空 | 32K，即 32768 个 Unicode 码点 |
| 连线说明文字 | 允许为空 | 1K，即 1024 个 Unicode 码点；仅纯文本 |

源文本使用 UTF-8 编码，长度按 Unicode 码点计数，不按 UTF-8 字节数计数。一个汉字按一个码点计；由多个码点组合而成的可见字符按其实际码点数计。达到上限的内容允许保留，超过上限的内容不符合长度约束。

空字符串和仅包含空白的文本都视为空文本。空格、制表符、换行等空白不构成有效标题。标题与卡片文本交换、空标题节点删除，以及其他空文本判断，统一使用这一规则。

逻辑优先在创建和编辑入口保持有效节点的标题非空，不先生成空卡片再依赖载入后的补全。普通新建使用默认标题“新节点”，复制保留原节点的有效标题；卡片文本和笔记仍允许为空，空字段的现有表达方式保持不变。

标题、卡片文本和笔记文本统一支持 Markdown 预览，以及内联和块级 LaTeX 公式渲染，按上述区域可见性规则展示；连线说明仅显示纯文本，不解析 Markdown 或 LaTeX。

### Markdown、公式与图片

三个文本区域采用相同的 Markdown 内容能力，均可包含标题、段落、强调、列表、引用、链接、图片、表格、代码块，以及内联和块级公式。节点标题也可以包含多行 Markdown 或块级内容；其中图片在收起时暂停渲染，展开后显示。字段的非空判断和长度限制仍针对源文本，不因预览隐藏某类内容而删除节点。

图片遵循 Markdown 图片引用方式，允许链接引用和内嵌存储，推荐使用链接，不建议把图片数据内嵌在文本中。这里区分的是图片资源的存储方式；Markdown 的行内写法和引用式写法均可引用外部图片。

- 链接引用可以指向在线资源或随图文件使用的本地相对路径；不强制把链接图片下载、转换成内嵌数据或打包进 HTML。
- 内嵌图片允许保留，源文本中的图片编码同样计入字段长度，不豁免既定上限。
- 图片链接指向的资源失效或无法加载时，在该图片原本的预览位置显示统一的固定警告：**图片无法显示：此处应有一张图片，但资源已失效或无法加载。**
- 警告替代的是图片的预览结果，原始 Markdown 图片引用保留，不能用警告覆盖源文本、删除引用或改变节点内容。编辑时仍显示原始源码，用户可以修改链接。
- 图片加载失败不影响同一字段其余文本、其他节点的显示或正常保存。预览中的警告不计入字段长度，也不触发空标题删除。

所有 Markdown 图片沿用相同的资源加载失败提示。只有当前应渲染的图片才显示加载结果或失败警告；收起时隐藏的标题图片和笔记图片不生成预览占位或失败提示。链接图片的可查看性取决于资源是否可访问；离线或宿主无法读取资源时同样显示固定警告，不要求为此改用内嵌存储。

### 长度上限与输入处理

文本长度在输入阶段控制，不把超限文本接纳为内存文档中的源文本：

- 普通输入的结果会超过对应字段上限时，拒绝本次新增文本，保留已接受的内容。达到上限后仍可删除文本，也可替换选中内容，只要替换后的总长度不超限。
- 粘贴文本超过剩余容量时，直接截断本次粘贴内容，只插入能够容纳的前缀；已有的未选中文本保持原样。有选区时，先扣除将被替换的内容再计算容量。没有剩余容量且未选中文本时，粘贴不改变字段。
- 标题、卡片文本与连线说明使用 1024 个 Unicode 码点上限，笔记使用 32768 个码点上限。截断也按码点执行，不按字节或 UTF-16 长度截取。
- 超限在输入时即处理，不保留“超限但等待用户修复”的编辑状态，不为此另设禁止保存、保存时截断或要求用户先缩短文本的流程。

这些输入规则约束页面中的用户编辑。Agent 或其他工具直接修改当前 HTML 图文件时，页面无法实时拒绝写入；打开或强制刷新读取到超限字段后，由逻辑硬截断，标题、卡片文本与连线说明各保留前 1024 个 Unicode 码点，笔记保留前 32768 个码点。只按长度保留前缀，不改为摘要，也不将超出部分转移到其他字段。

截断结果先进入本次载入的内存文档，手动保存后才写回硬盘；不增加后台自动追写。Agent 提示词明确节点三个文本字段及连线说明的上限与计数方式，并在逻辑部分规划辅助字数检查工具。这里处理的是当前 HTML 图文件自身的文本，不是节点链接或导入另一个文档。

### 节点与边的编辑焦点

对象编辑焦点指当前用于单对象操作或文字编辑的节点或边。同一张图同时至多有一个焦点对象，也可以没有焦点。节点获得焦点即进入已有的源码编辑状态；边单击后选中并可删除，但说明框隐藏，双击后才显示说明框并进入文字编辑，退出编辑后隐藏。批量节点选集是独立、仅在内存中维护的状态，与单对象焦点互斥，不让多个节点同时进入文字编辑。

- 普通选择模式下，鼠标单击命中的一个节点，该节点获得编辑焦点；节点须先满足无重叠约束，不提供叠放穿透选择。
- 新建节点自动获得编辑焦点，原焦点节点先按失焦规则收尾。
- 再次单击当前节点，或在该节点的标题、卡片文本、笔记文本之间切换编辑位置，保持该节点的编辑焦点，不视为节点失焦。
- 单击边时原节点失焦，边获得对象焦点；双击该边只是进一步编辑文字，不重新收尾另一个对象。边失焦时保留合法说明，空说明不删边。
- 切换到另一个对象或点击画布空白、工具栏等对象之外的位置，收尾原对象；节点执行交换或删除规则，边结束文字编辑。
- 点击工具栏连线入口后，后续节点点击用于选择起点与终点，不同时进入节点正文编辑；端点拖拽也不等于节点拖拽。

| 当前编辑焦点 | 操作 | 焦点结果 | 收尾 |
| --- | --- | --- | --- |
| 无 | 节点 A | 节点 A 获得焦点 | 否 |
| 节点 A | 节点 A 内部 | 保持节点 A 的焦点 | 否 |
| 节点 A | 节点 B | 切换到节点 B | 是，对节点 A 执行失焦处理 |
| 节点 A | 单击边 E | 边 E 选中但不开启文字输入 | 先处理节点 A 失焦，再确认 E 仍存在 |
| 边 E 选中 | 双击边 E | 保持 E 的焦点并编辑说明 | 不重复收尾 |
| 边 E 编辑说明 | 节点 B | 切换到节点 B | 接纳 E 的合法说明，退出边文字编辑 |
| 节点或边 | 画布空白、工具栏等对象之外 | 取消对象焦点 | 按原对象类型收尾 |

节点或边有焦点时，Delete 删除整个对象，即使光标位于该对象的文本输入区域。节点删除同时清除全部入边、出边；边单击选中后即可删除，端点节点不受影响。Delete 不作为字符删除键；退格、剪切、选区替换等文本操作继续按文本规则处理。删除仍先发生在内存中，手动保存才写盘。

批量选择时，Delete 对当前节点选集执行批量删除；既无单对象焦点也无批量选集时不删除旧对象。进入批量选择前先收尾原焦点，退出批量选择再恢复单对象编辑；批量选中不表示节点归属，也不写入 HTML。

A3 采用统一焦点粗描边，默认背景下为蓝色；节点编辑焦点、批量选中节点、选中边和当前查找定位对象共用这一外观。鼠标框选仅选择节点，不能框选边；全部选中节点有焦点描边，但不同时编辑文字。查找仅突出当前定位对象，不把它变成编辑或删除目标，不自动显示边说明。无鼠标悬停反馈或额外操作过程提示；这些状态和外观不写入源文本。具体规则见[外观设计 A3](appearance.md#a3-已确定的交互状态)。

### 新增节点的内容、焦点与关系

本节规定普通新建，复制另按批量规则处理。普通新节点立即创建，初始标题统一为“新节点”，并自动获得编辑焦点，用户可以立即修改标题。默认标题属于有效源文本，可以直接保留和保存；不先创建空标题节点再补写标题，也不需要先弹出标题确认步骤。

按[外壳 S4](shell.md#s4-已确定的功能入口)，工具栏形状按钮先根据点击前的节点编辑焦点分发：有节点焦点时只修改该节点形态，无节点焦点时才创建新节点。下述焦点、候选位置和自动连线规则描述通用新增操作，不表示点击形状总会新增；换形不调用这套新增流程，不改变节点标识、内容或已有关系。

通用新增操作按触发瞬间的原编辑焦点决定是否自动建立关系；这些自动边默认采用贝塞尔曲线，不受手动建边必须先选线工具的限制：

| 新建前的编辑焦点 | 新建结果 |
| --- | --- |
| 有焦点节点 A | 创建新节点 B，并建立一条 `A → B` 的有向关系；B 获得编辑焦点 |
| 无焦点节点，包括当前焦点为边或仅有批量选集 | 创建没有任何关系的新节点 B；B 获得编辑焦点，不从选集中自动选取连线来源 |

这里的默认连线只表达从原节点指向新节点，不自动附加归属、流程或依赖含义。关系建立由新建操作决定，与新节点最终位于何处无关。

若原焦点节点在新建过程的失焦收尾中因空标题被删除，新节点仍创建并获得焦点，但不保留以已删除节点为起点的关系，也不寻找其他节点代替。新节点随后因空标题被删除时，刚建立的连线也一并删除，原节点和其他节点保留。

### 新增节点的候选位置与避让

新增节点先按新建瞬间的焦点计算候选位置，再通过局部避让得到最终无重叠位置：

| 新建时的编辑焦点 | 初始候选位置 |
| --- | --- |
| 有焦点节点 | 放在该节点的右方或下方，卡片之间相隔默认距离 |
| 无焦点节点 | 新节点的中心位于浏览器内容视窗的正中央 |

默认间距比例初始取 **5%**，作为统一常量。向右放置时，间距为新建瞬间浏览器内容视窗宽度的 5%；向下放置时，为当时视窗高度的 5%。固定的是比例，一次新建所用的实际距离由当时的视窗尺寸确定；后续调整视窗大小，不重新计算已有节点的创建位置。比例仅在用户或测试人员反馈不合适时微调，不根据节点数量、拥挤程度或内容场景自行浮动。

完全禁止节点部分或完全重叠，不提供置顶、置底或逐层调整。候选位置若与其他节点冲突，移动到最近可用空位，必要时局部移动其他节点；5% 间距与视窗中心是候选规则，无碰撞时保留，有碰撞时以禁止叠放为优先。批量选集整体避让，保持内部相对位置。

新建位置只定义几何摆放；新建是否连线遵循上面的焦点规则，不通过相对位置推断任何关系。

### 拖拽与位置保存

首版不提供按关系或内容场景组织节点的自动排版，但必须执行局部碰撞避让。用户与 Agent 指定期望坐标，无冲突时保留，碰撞时调整目标或受影响邻居；不改写边，不自动收拢无碰撞节点。详见[逻辑 L4](logic.md#l4-已确定的禁止叠放与局部避让)。

单节点拖拽请求目标位置，批量移动对选集应用共同位移并保持相对位置；有碰撞时可以局部移动其他节点。边、内容及节点和出向边的源码顺序不变，拖入另一个节点不创建归属或连接，最终也不能停留为重叠状态。

节点坐标属于手动保存的文档内容，不再保存叠放顺序。保存输出局部避让后的有效坐标，不因重叠丢弃节点或禁止保存。分布不整齐、连线交叉或位于视窗外本身不触发排版；重开后只修正当前尺寸下的碰撞，不自动整理全图。

保存先完成编辑收尾、文本与格式校验，以及当前几何状态的局部避让。禁止叠放不改变空标题删除、有效内容保存或卡片展开状态不持久化的原则。

### 画布浏览与查找

打开或刷新后，在有效节点完成默认收起状态的测量与局部避让后，自动调整视野使所有节点可见；用户可以自行缩放。提供“回到原点”，不提供手动“显示全部”或“恢复 100%”。回原点与命中定位只平移视野，保留当前缩放比例。

A4 规定图内所有元素统一等比缩放，不保证最小可辨识尺寸，不因缩小而隐藏或改写内容。默认画布使用浅灰点阵，工具栏、查找工具与警告栏随主题配色，默认白底黑边；这些由外观及外壳呈现，点阵不生成源节点，缩放不改变源坐标。具体规则见[整体画布设计](appearance.md#a4-已确定的整体画布)。

查找仅以节点、边作为筛选条件；无筛选时查找全部有效文本，节点包含标题、卡片文本、笔记中的全部 Markdown 文本，边包含说明。收起的内容和未显示的边说明仍参与查找。按 S4 仅通过上／下箭头按钮定位上一个／下一个命中对象，不提供点击结果列表定位，输入和改变筛选本身不自动定位首项。定位节点时视窗中心对准节点中心，只突出当前定位对象，不自动展开卡片、进入编辑或显示边说明框；当前编辑焦点对象因移动、避让、尺寸或视窗变化离开视野时，自动跟随使操作区域保持可见。

视野和查找都属于页面状态，不写回节点位置，不保存平移、缩放、查询词、筛选条件或命中状态，也不保存派生查找索引。具体实现见[逻辑设计 L7](logic.md#l7-已确定的画布浏览与对象定位)。

### 批量操作的源文本结果

只提供批量移动、批量删除、批量复制，具体交互与操作边界见[逻辑 L3](logic.md#l3-已确定的批量操作)，不提供批量文字、样式或属性修改。

- 移动：选集使用共同位移，避让时也作为刚性整体，保持内部相对位置；允许必要的碰撞邻居移动，不改写边。
- 删除：删除选中节点及全部入边、出边；内部边按 ID 只删除一次，其他节点与无关边保留，不级联或重新挂接。
- 复制：新节点保留原节点全部有效内容、属性、样式引用与 Markdown 内容，分配新 ID；副本边也使用新 ID，保留说明、方向和连接位置。原有节点和边继续保留。

复制包含选中节点的所有关联边。以复制 A、B 为例：A→B 新增为 A′→B′，A→C 新增为 A′→C，C→A 新增为 C→A′；C 未选中则不复制，C→D 等两端均未选中的边也不复制。内部边、自环与平行边按原条目分别处理，不重复生成、不合并，也不沿关系递归复制更多节点。

副本保持内部相对摆放，整组寻找最近空位，禁止原位叠放；不复用普通新建的默认标题、5% 定位和焦点连线流程。批量操作与必要避让作为一次用户操作整体撤销，仍不提供重做。结果只在手动保存后写盘，选集、历史及绘制层级不写入源文本。

### 编辑与预览交互方案

采用由节点编辑焦点控制的两态交互：

| 节点状态 | 文本展示方式 |
| --- | --- |
| 处于编辑焦点 | 显示可编辑的纯文本源码，Markdown 标记及内联、块级 LaTeX 源码保持原样可见 |
| 不处于编辑焦点 | 显示 Markdown 预览，渲染内联、块级 LaTeX 公式和图片；无法加载的图片显示固定警告 |

上述切换只改变当前可见文本的编辑或预览方式。卡片形态仍显示标题与卡片文本，笔记文本仍需展开卡片才显示；获得编辑焦点不自动展开笔记。

失去节点编辑焦点时，先执行标题与卡片文本交换、空标题节点删除等收尾规则。节点保留时，再根据处理后的文本显示预览；被删除的节点不再显示预览。同一节点内部切换文本输入位置时，继续保持纯文本编辑状态。

源文本始终保存用户输入的 Markdown 与公式源码，预览结果不替换源文本。切换到预览状态不等于保存文件，修改仍须手动保存才写入硬盘。

### 用户手动编辑失焦处理

用户手动编辑过程中可以在输入控件草稿中暂时清空标题；该空草稿不写入内存源文本，源文本保留上一次有效标题。新建节点从“新节点”开始。原节点失去编辑焦点时，读取当前编辑草稿，使用统一空文本判断并按以下顺序收尾：

1. 如果标题为空、卡片文本不为空，交换标题文本和卡片文本。原卡片文本成为标题，原空标题成为空的卡片文本，笔记文本保持原样。
2. 完成上述处理后，如果标题仍为空，自动删除该节点，不保留空标题节点。笔记中是否存在内容不影响这一删除规则。
3. 标题不为空的节点保留，卡片文本和笔记文本可以为空。

| 失焦前的标题编辑草稿 | 失焦前的卡片文本 | 处理结果 |
| --- | --- | --- |
| 非空 | 非空或空 | 保留节点，不交换内容 |
| 空 | 非空 | 交换标题和卡片文本后保留节点 |
| 空 | 空 | 自动删除节点，不因笔记非空而保留 |

交换或删除作为一次内存文档更新完成，不先把空标题写入源文本再处理。这里的空标题删除指用户编辑草稿收尾，不用于擅自删除从硬盘读取的标题异常节点；即使被编辑节点充当层级根节点，也不设置例外。主动删除和空标题自动删除使用下述同一套节点与关系删除规则。

交换和自动删除先作用于内存中的当前文档，仍遵循[架构主要原则](architecture.md#主要原则)：用户手动保存后才写回硬盘，失焦处理不自动保存文件。

### 节点删除与剩余内容

主动删除和空标题失焦后的自动删除采用同一套规则：

1. 删除目标节点及其全部内容。
2. 清除所有以该节点为起点或终点的边，不根据说明内容区别处理。
3. 保留其他节点及其内容，保留其他节点之间原有的关系，不自动补建或重接任何关系。

删除节点不会沿关系级联删除其他节点，也不会自动提升子节点、选择替代根节点、归并分支或把孤儿节点挂到其他节点下面。

离散节点和删除相邻节点后留下的节点允许存在并直接保存。“孤儿”只是对失去原连接的节点的描述，不是预设的父子身份；该节点仍可能拥有其他入边或出边，不等于指向不存在对象的无效关系。插件保留其现状，不因为失去连接而自动修改其他关系。

| 删除情况 | 结果 |
| --- | --- |
| 普通节点或叶节点 | 删除该节点及全部入边、出边，其余节点和关系保持原样 |
| 具有出向连接的节点 | 目标节点失去来自被删除节点的入边，保留它们与其他节点的已有连接；不重新挂接 |
| 某棵层级树的根节点 | 剩余分支分别保留，可以具有多个根；不自动指定共同根节点 |
| 最后一个节点 | 得到允许保存的空图，保留格式与样式等文档信息，不自动创建占位节点 |

所有图都按通用有向关系保留删除结果，不要求剩余内容形成树或森林。删除后其余节点保持原坐标，不自动重排或改写关系；多个入向关系、回路或没有根节点都不影响源文本保存。

用户主动删除属于可撤销的完整操作，撤销时一起恢复目标节点和本次清除的全部关联边。空标题失焦删除属于不可撤销的自动操作，节点及随之清除的边均不恢复，也不能通过撤销此前的清空或其他编辑间接恢复。节点尚未被自动删除时仍可正常撤销文本编辑。两种删除共用清理规则，但操作来源和撤销资格不同。撤销记录不属于 HTML 源文本，任何刷新清空，包括手动保存引发的刷新。

### 已确认的节点关系

整张图由节点与有向边组成。节点之间不预设父子、归属、流程或依赖关系；只有实际存在的边建立从起点到终点的连接。取消基础关系类型清单，所有边采用同一套表达，不再存储或选择关系类型。整张图不设置图类型，节点不设置业务类型；节点几何形态只决定外观，不为节点自动创建关系。

- 通用模型允许独立节点、多条互不相连的分支、多个入向或出向关系、有向回路及自环，不为连接所有节点而强制创建共同根节点。
- 一条边只规定起点指向终点；具体含义由节点内容、边的方向和可选说明共同表达，不要求选择“包含”“流程”“依赖”“引用”等内置类别。
- 树和森林只是这套有向关系能够表达的特例，不再作为独立的源文本结构规范；不强制无环、单父、连通性或根节点数量。
- 同一节点可以接收多个节点的边，同一对端点之间也可以存在多条边，按各自标识独立保存。即使说明文字相同或为空，也不自动合并。
- 思维导图、流程图等只是用户组织内容和有向边的方式，首版不据此自动排版，也不重新施加已取消的树状结构限制；HTML 嵌套或节点的出现位置不定义业务父子关系。

通用新增操作有焦点节点时，仍按已定规则自动添加从原节点到新节点的一条默认贝塞尔边，不赋予默认父子身份或特殊边类别；没有焦点节点时，新节点保持无连接。用户手动创建连线必须先选择工具栏中的线工具，可按 A2 选择贝塞尔、直角折线或直线外观，再选择起终点，初始说明可为空。复制保留全部关联边及原有路径外观；自动创建且未指定外观时采用贝塞尔。Agent 直接编辑 HTML 不经过页面选线步骤。

边的说明文字是用户内容，不是类型编码。写入“依赖需求”“包含某项”等说明不触发专属校验、归属推断、自动排版或其他隐藏行为；不能用说明关键词、颜色或线条外观重建被取消的关系类型系统。

有向关系自身可以附带说明文字，用于说明条件或关系含义。说明可为空，最多 1024 个 Unicode 码点，仅支持纯文本；`**强调**`、`$公式$` 等写法按原字符显示，不解析 Markdown 或 LaTeX。输入、粘贴与 Agent 写入超限时沿用对应的拒绝或硬截断规则；空说明不删除关系。

独立建边通过工具栏连线入口依次选择起点和终点；点击可以在节点内部，连接点分别取距离点击位置最近的节点边缘点。单击边选中且保持说明框隐藏，双击才显示并编辑说明，退出编辑后隐藏；拖动起点或终点到另一节点分别修改该端，保持边标识、另一端和说明。首版不提供折线形态编辑，用户选择的端点连接位置随手动保存保留；路径形状由逻辑计算。具体交互见[逻辑设计](logic.md#l1-已确定的连线交互)。

具体内容场景的Markdown 内容按产品需要继续设计，不预先增加新的边类型枚举。树形图使用同一套节点和有向边表达，不额外存储父节点字段或嵌套树，也不提供子树折叠功能。

### 与属性和外观的关系

节点的三部分文本、节点属性和样式选择是不同的信息。源文本继续记录节点属性、节点间关系，以及节点形态和图的样式引用；具体外观由外观部分定义。

选择另一种节点外观，不改变节点标题、卡片文本、笔记文本的含义，也不自行改变边的起点、终点或说明。

### 通用有向图与节点形态

所有新建图统一为通用有向图，没有思维导图、流程图或自由画板等文档类型字段与切换入口。用户通过内容、节点位置和有向边组织所需的图；具体用途不引入另一套格式或约束。

新增节点由工具栏提供，启动形态为圆角矩形、直角矩形、菱形、平行四边形和圆形，后续按实际需要扩充。形态可自由混用，已有节点也可自由切换形态。所有形态使用同一套卡片内容模型，不区分图片、图表、判断或人员等业务节点类型。

切换形态只更改外观引用，保留标题、卡片文本、笔记、Markdown 内容、资源引用和全部有向边；不以形态筛选内容，不转换、清空或丢弃任何有效内容，也不增加“不兼容类型转换”流程。尺寸变化继续按 L4 局部避让并更新连接点；一次形态切换及其联动位移作为完整用户操作撤销。

三部分文本、长度限制、编辑焦点、失焦收尾和保存规则继续通用。具体规则见[逻辑设计 L6](logic.md#l6-已确定的通用图与节点形态)。[节点形态与内容场景](diagram-types.md)保留内容目标，不再定义图类型或业务节点类型枚举。L8 已限定图片与表格只用 Markdown，排除手绘、表格额外能力、分区、线框和模板；时序通过有向边表达，不恢复节点分类。

### 源文件异常的分类处理

逻辑按问题种类处理，不对所有异常统一补全：

| 情况 | 已确定的处理 |
| --- | --- |
| 避免空标题节点 | 创建时直接设置“新节点”；编辑中的空标题只留在控件草稿，收尾时按既定规则交换或删除，不自动给已有异常文件填标题或补正文 |
| 缺少节点位置 | 先在原点半径 5 个图坐标单位内生成候选，再局部避让；最终坐标可以超出半径 5 |
| 节点发生重叠 | 根据实际外框局部避让，保留内容与边；不通过层级覆盖、删节点或禁止保存处理 |
| 多个节点使用相同 ID | 按源文本检查顺序只保留第一个节点，删除后续同 ID 节点及其自身内容，不合并内容或生成新 ID 保留副本 |
| 连线指向不存在的节点 | 取消该连线，不创建占位目标，不改指其他节点 |
| Agent 直接写入超长文本 | 读取时硬截断，标题、卡片与连线说明保留前 1024 个码点、笔记保留前 32768 个码点；不在页面尝试实时拦截 Agent 的磁盘写入 |
| 无法自动处理的错误 | 在网页右上方警告栏集中警告，展示有效部分并允许继续编辑；手动保存只写出有效内容，无法处理的内容不保留 |

“第一个”以 HTML 文档中节点的出现顺序为准，不以屏幕位置或从根节点遍历的顺序为准。指向重复 ID 的边继续连接第一个节点，副本的出边不合并；碰撞问题随后独立避让，不能为减少重叠而优先保留后出现的副本。

随机值只作为缺失位置的初始候选，不替代 P3 新建规则；本次载入只抽取一次，再按节点尺寸避让。最终坐标在内存中稳定，未保存的原文件重新载入时可以重新生成候选；保存后已有有效位置不再随机，只在实际发生碰撞时修正。

处理结果先进入内存文档，手动保存后写回硬盘。不把这些明确规则扩展成任意删除、截断、重命名或猜测未知字段；图片资源不可用继续使用 P6 的固定警告。

右上方警告栏集中显示无法自动处理的问题，说明位置和原因。有效节点、有效字段及有效连线继续展示并可编辑；手动保存时，从当前有效数据生成图文件，不写出无法处理的节点、内容或连线。无效节点的全部入边、出边也不进入保存结果，避免留下无目标引用。警告属于界面状态，不写入源文本。

有效内容包括当前因卡片收起而隐藏的笔记、标题图片及其源数据，不能把“有效部分”理解成只保存屏幕上可见的内容。读取和警告本身不改写硬盘；只有手动保存才将有效结果写回。无需为错误内容增加原文保留、局部补丁或恢复机制。

### 需要用户确定的产品问题

已确定的产品问题：

- P1：采用通用有向边表达节点间关系，取消基础关系类型；树是其特例，不预设父子结构，不设置树专属拓扑限制与子树折叠。
- P2：统一删除目标节点及全部入边、出边，保留其余节点和关系；允许保存空图和孤立节点。
- P3：普通新建使用“新节点”并聚焦，有原焦点时连线；右方／下方的 5% 间距或视窗中心是候选位置。L4 要求最终无重叠，允许局部避让；手动保存修正后的坐标，不保存叠放层级。
- P4：重新打开或刷新时全部收起，鼠标长按 1 秒或点击右上方圆形按钮展开；展开为固定尺寸，标题区冻结置顶，卡片内容与笔记滚动，收起时笔记不可见、卡片内容仍可滚动查看。
- P5：普通输入超限时禁止新增，粘贴超限时截断本次粘贴内容；输入阶段保证长度，不另设超限禁止保存流程。
- P6：三个文本区域均支持 Markdown、内联及块级公式；收起时标题图片不渲染，卡片内容中的完整渲染，笔记全部隐藏。图片推荐链接引用，允许内嵌，加载失败以固定警告替代预览。连线说明只支持纯文本，上限 1024 个码点。
- P7：异常分类处理；缺失位置先在原点半径 5 内生成候选，再局部避让；同 ID 保留第一个，无目标边取消，Agent 超限文本硬截断。无法处理的内容警告并排除，只保存有效部分。重叠保留节点并修正坐标，不再补齐叠放字段。

本轮 P1–P7 的规则按以上记录接入；缺失或不支持的格式版本、无法可靠识别的节点结构、无法解释的必需内容，以及从硬盘读取的空标题，归入右上方警告栏警告，不猜测补全；无法处理的部分排除在有效数据及保存结果之外，不阻止其他有效部分编辑和保存。边没有类型字段。超限字段按已定规则硬截断并保留处理记录。这里的正文是当前 HTML 图文件中的字段，不是节点引用另一个文档。强制刷新与丢弃未保存编辑的原则不变。

图片资源加载失败已经明确采用固定警告，不作为需要整份文档修复的源文本格式错误。[逻辑设计草案](logic.md)记录已定的连线、撤销、批量、局部避让与形态切换规则，以及已定的 L7 视野查找与 L8 内容范围；自动排版延期至手动排版完整可用之后，按具体布局场景再设计，不恢复图类型字段。当前内容边界见[内容范围](diagram-types.md)，不为已排除的能力预设字段。

## 技术草案

### 草案状态与表达方向

优先使用 HTML 原生的 `id`、`class`、`href` 和元素结构，只有无法合理表达的信息才使用 `data-*`。已确认的产品语义是节点与不分类的有向边，以及每个节点的标题、卡片文本和笔记文本。

运行时采用 HTML 节点内容与 SVG 连线。可见连线路径和 KaTeX 生成内容均是派生预览；手动保存仍从有效模型序列化既定文本、位置和关系，不序列化渲染 DOM，不为 SVG 路径增加第二套关系源。

用一个源文本容器表达一张图，所有节点平级存放为容器的直接 `article` 子元素。每个节点在自己的关系列表中声明出向关系；目标通过同一图中节点的标识引用。HTML 嵌套仅组织字段，不定义业务上的父子关系。

层级也使用有向关系表达，不额外维护嵌套节点树、父节点字段或另一份权威连线列表。入向与出向关系索引由这一份关系数据派生，首版不生成自动排版结构；索引保留完整的关系集合，不把多个上游节点压缩为一个父节点。

### 格式版本与标识

第一版源文本格式在完整 HTML 的 `head` 中使用 `<meta name="format" content="mindmap/1">` 标识，并声明 UTF-8 编码。格式版本描述源文本的读取约定，与插件或渲染依赖的软件版本分开。下方示例仅展示图容器片段，不重复完整页面的头部与外壳。

完整图文件通过原生 `link` 与外部 `script` 引用同一明确版本的本地公共资源，引用使用相对路径；不新增承载运行库或字体载荷的源字段，也不将工具栏等生成界面存入文件。版本目录和空图完整文档示意见[目录与引用草案](shell.md#目录与引用草案)。资源版本由引用表达，与 `mindmap/1` 的源文本格式标识分开；普通保存保留引用，不自动升级。

读取时检查格式标识；缺失或不支持的版本产生明确诊断，不猜测另一套结构或静默改写。后续字段变化是否需要升级格式，由开发方根据兼容性决定。

逻辑自动创建节点时使用 `node-1`、`node-2` 等递增名称作为 `id`，分配前检查整份 HTML 的现有标识并跳过已占用值。同一运行会话内分配序号持续递增。Agent 可以使用 `root`、`requirements` 等有意义的名称；读取时保留已有标识，统一检查非空、无空白和文档内唯一性，不强制批量重命名为自动编号。

关系同样使用原生 `id`，自动生成时采用 `link-1`、`link-2` 等名称，并与节点及外壳共同检查文档内唯一性。这里的 `link-` 只是标识命名前缀，不是边类型。修改边的起点、终点、连接位置或说明时保留标识。节点即使命名为 `root`，也不因此获得特殊身份；数据恰好为树时可由关系计算根节点，一般有向图不要求存在这样的节点。

### 标签与属性命名原则

名称优先使用一个或两个含义明确的单词，保持简短、可读。省去项目缩写前缀；能够由所在元素判断的图或节点上下文，不在每个属性名中重复。避免为了缩短名称而使用难以理解的单字母缩写。

节点和关系标识使用原生 `id`，外观引用使用原生 `class`，关系终点使用原生 `href` 引用。标题、卡片文本、笔记文本和出向关系列表分别通过简短的结构类名 `title`、`card`、`notes`、`links` 识别。

结构类名用于识别内容，外观类名用于引用 CSS 样式。`map`、`title`、`card`、`notes`、`links` 是通用结构类名，不再设置字段外的 `data`、`members` 内容结构；示例中的 `default`、`basic` 是外观类名，`round-rect`、`rect`、`diamond`、`parallelogram`、`circle`是节点形态类名。更换外观时只调整外观类名，保留结构类名；外观名称不占用结构类名。读取时按独立类名匹配，不依赖整个 `class` 字符串及其排列顺序。不再使用 `children` 容器表达关系。

节点和关系 `id` 按整份 HTML 检查唯一性，包括与外壳和其他元素的冲突。载入时多个节点同 ID 按文档顺序保留第一个并删除副本；关系 ID 重复、节点 ID 与外壳或关系元素冲突不套用节点去重规则，而进入右侧诊断。有效编辑模型保持标识可唯一解析，无法处理的冲突对象不写入保存结果，不阻断其他有效部分保存。修改文本、移动节点或更换外观时保持标识不变；生成预览时不复制源元素 ID 造成新的冲突。

图容器、节点和边均不设置 `data-type`，不维护图类型或业务节点类型枚举。节点形态是外观引用，使用 `class` 中的短类名表达。原生 `href` 表达终点，其所属出向列表确定起点。后续新增信息也先检查原生属性和元素结构能否合理表达，再决定是否增加自定义数据属性。原生 `style` 仍表示内联 CSS 声明，不用来存放外观名称；节点标题由文本元素承载，不借用原生 `title` 属性。

结构识别只在对应图的源文本容器内进行，不把外壳中恰好使用相同标签或类名的元素识别为图节点；`id` 的唯一性则按整份 HTML 检查。

### HTML 表达建议

| 信息 | 建议表达 | 说明 |
| --- | --- | --- |
| 图的源文本容器 | `<section class="map">` | 通过元素及结构类名界定一张图的源文本范围 |
| 图样式引用 | 图容器的 `class`，例如 `class="map default"` | 保留结构类名 `map`，用 `default` 引用图的外观 |
| 节点与节点标识 | `<article id="plan">` | 图容器的直接 `article` 子元素表示节点；所有节点平级，标识唯一且稳定 |
| 节点形态 | 节点 `class` 中的 `round-rect`、`rect`、`diamond`、`parallelogram`、`circle` | 只引用几何外观，不表示业务角色或限制可包含的内容 |
| 节点样式引用 | 节点的 `class`，例如 `class="basic rect"` | 引用节点外观，不代替节点属性 |
| 节点位置 | 节点的 `data-x`、`data-y` | 卡片左上角的图坐标，不记录受视窗平移和缩放影响的屏幕坐标 |
| 节点标题 | `<h2 class="title">` | 节点自身的标题文本 |
| 节点卡片文本 | `<div class="card">` | 节点自身的卡片文本 |
| 节点笔记文本 | `<div class="notes">` | 节点自身的笔记文本 |
| 出向关系列表 | `<ul class="links">` | 每个节点直接包含的关系列表，无出向关系时保留空列表 |
| 单条有向边 | `<li><a id="link-1" href="#target">条件说明</a></li>` | 一个列表项直接包含一条边，起点是该列表所属节点，终点由 `href` 指定；无类型字段，元素文本为可选说明 |
| 连线外观 | 关系元素上的 `class`，可取 `bezier`、`orthogonal`、`straight` | 只描述路径外观，缺省为贝塞尔；不是业务类型 |
| 起点与终点连接位置 | 关系元素上的 `data-start="1 0.25"`、`data-end="0 0.75"` | 可选的节点局部归一化连接点，分别属于源节点和目标节点；不替代起点归属或 `href` |

每个节点直接包含三个文本字段元素和一个出向关系列表。字段元素存在与文本非空是两项不同约束：标题文本必须非空，卡片文本和笔记文本可以为空，但各自的字段元素仍保留。关系元素内的文本是可选显示说明，始终按纯文本处理。

关系说明最多 1024 个 Unicode 码点，直接读取关系元素的文本内容；序列化时转义 HTML 字符，预览按文本输出，不传入 Markdown 或数学解析器。截断说明不改变关系 ID、方向与端点，空说明也不删除关系。

图片与表格均放在三个 Markdown 字段内，不额外补充原生 HTML 内容元素或配置属性。首版使用 `default` 默认主题与 `basic` 基础节点样式，结合下述五种形态引用，不建立主题选择能力；具体 CSS 参数由外观技术草案落实。

### 节点形态引用草案

所有图都使用相同的 `section.map` 与平级 `article` 结构，不增加 `directed` 默认类型或用另一字段替代已取消的图类型。节点没有业务类型；圆角矩形、直角矩形、菱形、平行四边形和圆形只是同一内容模型的不同外观。

| 工具栏形态 | 外观类名 | 源文本示例 |
| --- | --- | --- |
| 圆角矩形 | `round-rect` | `<article id="node-1" class="basic round-rect">` |
| 直角矩形 | `rect` | `<article id="node-2" class="basic rect">` |
| 菱形 | `diamond` | `<article id="node-3" class="basic diamond">` |
| 平行四边形 | `parallelogram` | `<article id="node-4" class="basic parallelogram">` |
| 圆形 | `circle` | `<article id="node-5" class="basic circle">` |

上述类名是技术草案，具体 CSS、尺寸与内容区域由外观部分实现。每个节点采用一个持久化的收起形态类名；工具栏有节点编辑焦点时把所选形态交给该节点的换形逻辑，无节点焦点时才调用通用新建。技术初始默认与参考外观一致，使用圆角矩形：无明确形态的通用创建操作或缺少形态引用的文件使用 `round-rect`，不恢复 `content` 节点类型。

读取到未知或冲突形态引用时，记录外观诊断并使用默认圆角矩形外观；有效模型移除无法使用的形态引用并记录 `round-rect`，保留有效内容和边，等待手动保存。外观异常不能将完整节点或其内容判为不兼容。其他合法皮肤类名保留，不从标题或数据猜测节点业务类型。

形态切换只替换这个收起形态类名，不改写三个文本字段、内容结构、资源引用、ID、属性或边。展开仅是运行时状态，不把 `diamond`、`parallelogram`、`circle` 或 `rect` 改存为 `round-rect`。展开时主动切换形态只更新保存的形态及标题栏标识，可见外框仍是圆角矩形；不另存缩略图或一份原始形状。每种支持的形态都必须提供可访问的内容区域：长文本仍能滚动查看，不能用圆形、菱形或平行四边形轮廓永久裁掉正文；展开状态继续沿用固定尺寸、置顶标题和正文滚动规则。

`round-rect` 与 `rect` 明确区分圆角和直角，`parallelogram` 使用单个完整单词以避免含义歧义。现有示例中显式记录的 `rect` 继续表示直角矩形，不因为默认形态调整而改写已有节点。

旧草案中的图类型和业务节点类型编码表取消，`group` 也不作为预留节点类型。未来工具栏扩展仍以实际产品需求为依据，不能为添加内容先建立互不兼容的节点子类。

### 关系编码与约束

A2 已确定三种连线外观：默认贝塞尔曲线，也允许创建直角折线或直线。它们仅是路径外观，不是业务关系类型。曲线与直角折线绕开无关节点；直线可被节点覆盖。说明框属于边，按 A3 仅在双击进入说明编辑后显示；显示时全文扩张，中心默认位于所属路径的弧长中点，自动避让时仍保持中心在线上，通常避开节点和其他可见说明框。隐藏框不参与避让，完整说明仍可保存、计数与查找。直线空间不足时，说明框优先级低于节点并允许被节点遮挡；按[遮挡例外](appearance.md#直线说明框的遮挡例外)暂不解决该极端情况，完整文本与中心约束保留。

关系起点由所属节点确定，终点使用同一图内的片段引用，例如 `href="#requirements"`。序列化时对目标标识作片段编码，读取时解码一次后按节点标识查找；外部 URL、其他图的节点或外壳元素不能作为这里的关系终点。正文中的普通 Markdown 链接不属于关系列表，不自动生成图中的关系。

关系元素保存边标识、终点引用、可选说明、可选连接位置及连线外观引用；起点由所属列表确定。边不使用 `data-type`，不设置业务类型枚举、默认业务类型或业务类型选择入口；创建时选择路径外观不恢复业务分类。图容器和节点也不再写入或校验业务类型属性。

每条关系保存一次；入向关系由扫描出向关系列表建立索引，不再写入另一份入向列表。不同关系可以连接同一对节点，凭关系 `id` 区分，不能只按起点和终点合并它们。关系显示文本为空时仍是一条有效关系。

有原焦点节点的通用新建命令创建一条说明为空的默认贝塞尔边，追加到原焦点节点的 `ul.links`；工具栏默认建贝塞尔边，也可先选直角折线或直线外观，再依次选择起点与终点。默认说明为空，不添加任何业务类型属性。修改节点内容、节点形态或其他外观均不自动重分类或重建边。

通用校验检查边标识、端点、说明与可选连接位置，不执行关系类型校验，也不执行无环、单父、连通性或根节点数量校验。这适用于全部图；回路、自环、多个入边、平行边和多个独立部分均按原样读取与保存。

说明文字不参与结构校验或业务分类；即使文字描述了包含、流程或依赖，也只是用户内容。数据是否恰好构成树不影响首版手动摆放，也不能作为文件合法性的前提。算法需要遍历关系时使用已访问标识等机制避免在回路中重复执行，不通过禁止回路来简化处理。

空图是有效文档。`section.map` 保留样式引用等信息，但可以不包含任何 `article`；此时也没有关系。格式标识等文档信息仍保留，不生成空标题节点或占位根节点。读取、校验、保存和重新打开均须接受空图。

编辑与连线更新的邻接索引从边派生，不需要根节点字段。节点和边的源顺序保持，不作为叠放信息；避让只改坐标，不重排源文本或修改关系。

首版直接使用有效源坐标，不执行树布局或一般有向图的自动排版，也不在两类算法之间自动回退。后续按具体布局场景设计自动排版时，算法适用性仍与源文本有效性分开；不得为套用算法删除、反转或补建源关系，也不得因此拒绝保存格式有效的文档。

若读取到旧草案在图容器、节点或边上保留的 `data-type`，不解释其值、不回填默认类型；将该废弃属性作为可选异常内容提示并从有效模型排除，保留其他字段有效的图、节点与边。不能因为旧类型属性删除节点内容；保存结果不输出该属性。这仅是读取规则，不增加迁移工具或另一套关系模型。关系模型也不包含子树或分组折叠字段。

### 连线外观与说明框的源文本表达

使用关系元素的原生 `class` 保存创建时选择的路径外观，不新增业务类型字段：

| 连线外观 | 类名 | 说明 |
| --- | --- | --- |
| 贝塞尔曲线 | `bezier` | 默认值，既有无外观类名的边按此显示 |
| 直角折线 | `orthogonal` | 自动生成水平／垂直线段的路径 |
| 直线 | `straight` | 保持笔直，允许被节点覆盖 |

例如 `<a id="link-1" class="orthogonal" href="#target">说明文字</a>`。保存与批量复制保留所选外观；缺省时使用 `bezier`，无法识别或互相冲突的外观类名按可选外观异常提示并回退默认，保留其他有效边数据。

说明文字仍是同一个 `a` 的纯文本内容，最多 1024 个 Unicode 码点。界面中的说明框不是新的 `article`、卡片笔记或独立关系；其自动尺寸、路径位置、显示状态和用于区分交叉的颜色不写回正文或新增持久化字段。单击选中、悬停和查找不显示说明框，仅双击进入编辑后显示，退出编辑隐藏；隐藏不删除源文字，也不影响计数和查找。空说明保留边，同样可双击打开输入框。

直线说明框被节点遮挡仅影响当时画面，仍是有效说明，不按源文件异常排除，不因遮挡改写文字、边或节点坐标；保存与查找继续使用完整文本。显示优先级不增加源文本字段。

“完整显示”适用于正在编辑的说明框内、上限内已经接纳的文本，不取消输入限长、超限粘贴截断或 Agent 超长写入的硬截断。可见说明框仍按全文排版与扩张，直线遮挡例外不等于允许删字或改成短预览。非编辑状态不展示说明框；保存仍从有效模型输出完整文本与路径外观，不从渲染后的说明框读取或截取可见文本。

### 连接点与端点改接

连接位置采用短属性 `data-start` 与 `data-end`，每个值是两个空格分隔的有限十进制数 `u v`，均在 `[0, 1]` 内，对应所属节点外框内的横向与纵向比例。它们表示连接位置，不保存节点 ID，也不表示折线路径上的中间点。

建边或改接时先取鼠标到可见节点外轮廓的最近点，再按该节点外框归一化。例如矩形外框上的 `1 0.25` 表示右边缘自上向下四分之一处，`0 0.75` 表示左边缘四分之三处。两端分别使用各自节点的局部坐标，不能直接存浏览器视窗坐标。

```html
<li><a id="plan-requirements" href="#requirements"
  data-start="1 0.25" data-end="0 0.75">需求分支</a></li>
```

节点移动时连接点随节点移动，相关 SVG 连线路径在拖动过程中实时更新，不等待拖拽结束；尺寸、形状或卡片展开状态改变时，将局部比例点投影到当前可见外轮廓，保持贴边：收起贴合所选形态，展开贴合统一圆角矩形；展开期间仅改变收起形态而显示轮廓不变时，不因该变化重新改写连接位置。投影结果仅用于显示，不因渲染而反复改写保存值；相同外观与尺寸下重开可恢复同一连接位置。连接点同距时采用稳定的技术选取顺序，不要求用户决定几何算法。

两个属性可各自省略，兼容未指定连接位置的已有源文件与自动生成关系；缺失的一端由路径逻辑自动计算显示位置，不因此补建关系或移动节点。值格式错误或越界时，对该可选属性给出警告并从有效模型排除，该端退回未指定位置的显示方式；有效的另一端、关系本身及说明继续保留。仅凭归一化数值不能要求静态校验器测量实际 CSS 轮廓，贴边由显示阶段投影保证。

端点改接在内存中作为一次关系更新完成：

- 修改起点：把原来的同一个 `<li>` 关系条目移到新起点的 `ul.links` 末尾，更新 `data-start`；保持关系 ID、`href`、`data-end` 和说明。其他关系在各自列表中的相对顺序不变。
- 修改终点：保留条目所在列表与位置，只更新 `href` 和 `data-end`；保持 ID、起点、`data-start` 和说明。
- 单独删除边：仅移除指定 ID 的关系条目，不删除两端节点，也不删除同端点的其他平行边。

拖动节点仍不改变任何关系或源码顺序；拖动连线端点是不同操作，起点变化要求调整源文本归属，不能保留在旧起点列表或另外增加一份起点字段。未完成的建边、端点拖拽草稿、选中状态、说明输入状态和中间路径不写入源文本。保存时保留已确定的有效连接位置，不支持手动折点数据。

### 批量复制的标识与关系表达

对选集 `S` 中每个节点分配新 ID，建立原节点到副本的映射。复制操作前至少一端属于 `S` 的每条边一次：选中端替换成对应副本，未选中端保留原节点，副本边另分配新 ID，保留路径外观。实际存储仍只有各节点的出向列表，不增加副本来源、批次或另一套关系字段。

内部边写入源节点副本的 `ul.links`，外部出边也写入副本；外部入边的副本必须追加到原外部源节点的 `ul.links`。例如 C→A 的副本 C→A′ 仍存放在 C 中，不能误放进 A′ 的列表或倒转方向。原有边条目及相对顺序不变。

副本节点按原节点源顺序追加，副本边按操作前遍历顺序追加到映射后的源列表，保留说明、路径外观与连接位置。副本整组平移到无碰撞位置，不生成层叠字段。Markdown 图片与表格属于文本字段，按原源码复制；正文和资源 URL 不做全局替换。见[批量技术接入](logic.md#批量选择与三种操作的技术接入)。

### Markdown 图片与表格表达

图片和表格只记录为 `h2.title`、`div.card`、`div.notes` 中的 Markdown 文本。图片沿用标准行内或引用式语法；表格沿用已选 Markdown 表格语法，使用表头、分隔行和单元格文本表达 Excel 式行列表格。内容随字段完整计入既定字符上限。

不再使用字段外的 `img`、`table.data`、`table.members`、`time`、笔画数据或 `data-slot`、`data-chart` 扩展。图片和表格的归属由所在文本字段直接确定，不需要额外标记。Markdown 表格遵循该字段的普通块内容可见性；图片继续使用标题收起时不渲染、卡片内容可见、笔记收起时隐藏的规则。

HTML 仍是文档外壳与节点字段的存储格式。Markdown 预览生成的 `img`、`table` 等 DOM 是渲染结果，不等于支持用户输入原生 HTML 内容语法，也不反向写回源文本。字段中的原始 HTML 片段不作为图片、表格或其他扩展功能执行、渲染；原字符串仍按普通文本规则计数和保存。已经编码进字段的内容不能因为形态切换而被删除。

旧草案中字段外的Markdown 内容不再是当前支持格式；无法处理的可选部分按既定规则警告并排除，保留有效的三个文本字段和边，不建立自动转换器。删除异常原文的规则不扩展为删除有效 Markdown 内容。

不增加直接单元格编辑、表格公式计算、Excel 文件读写或成员字段编辑器。已有 LaTeX 公式仍按文本预览规则处理；时序仅通过有向边及纯文本说明表达，不增加消息、时间轴或时间字段协议。

### 读取与更新建议

1. 识别 `section.map` 的源文本范围，再按 HTML 文档顺序收集其所有直接 `article` 节点；先处理重复节点，再建立保留节点的标识索引。不要求从某个根节点出发才能发现其他节点。
2. 只读取各节点自身的直接 `h2.title`、`div.card`、`div.notes` 文本字段，以及直接 `ul.links` 中每个直接 `li` 所包含的唯一直接 `a` 关系元素。先收集全部节点，再解析目标引用，允许引用文件中后出现的节点。
3. 每条边的起点为关系列表所属节点；读取边自身的 `id`、`href`、显示文本以及可选 `data-start`、`data-end`。以去重后的节点集解析终点，取消指向当前图中不存在节点的连线，再派生入向关系索引；不读取边类型或预建父子结构。
4. 节点与出向关系按源文本中的出现顺序读取和写回；不根据节点排列顺序创建父子关系或普通连线。
5. 普通文本修改只更新对应节点的对应字段；标题编辑草稿为空时不覆盖已接受的非空标题。失焦时读取草稿，执行标题与卡片文本交换或删除节点，保证源文本不经过空标题中间态。
6. 修改节点间连接时，增删或修改对应的边元素；更换起点时将条目移到新起点的列表中。节点仍平级存放，其他边保持不变。删除节点调用下述统一操作，清除全部关联边，不留下无效端点或自动补建关系。
7. 更换外观时只修改所属图或节点的外观类名，保持结构类名、标识、全部内容以及所有关系不变。
8. 读取、修改、校验与保存始终覆盖全部节点与关系，包括没有入向或出向关系的节点和隐藏笔记。不能仅保存从某个节点可达的部分，也不能从当前可见预览反推源文本。
9. 读取节点坐标，以当前可见卡片尺寸检测碰撞并局部避让。结构有效不等于几何无重叠；先得到无碰撞的有效模型再显示和编辑。保存写入最终坐标，不读取或输出叠放层级。

这里的 `section.map` 等写法表示标签与类名的组合；结构识别按直接子元素和独立类名进行，不按样式颜色、视觉位置或整个 `class` 字符串推断关系。

### 新建位置与避让的逻辑接入

本节规定新建候选、坐标恢复、局部避让与持久化。只有最终节点坐标进入源文本；对象焦点、卡片展开、批量选集、视野变换、查找状态和渲染内部层次不保存。几何计算不推断或修改边。

默认比例使用 TypeScript 常量 `const NEW_NODE_GAP_RATIO = 0.05`。只在用户或测试人员反馈间距不合适时调整该值，不引入按拥挤程度自动变动的比例或间距钳制。每次新建使用当时的浏览器内容视窗尺寸，已有节点不绑定持续变化的视窗百分比样式。

候选方向与对齐采用既有技术默认值：页面摆放方向明确为纵向时向下，否则向右；没有方向约定时默认向右。该约定只生成初始候选，不是自动排版模式；若有碰撞，避让允许改到其他方向的最近空位。

#### 位置计算

以承载导图页面的浏览器内容视窗的 CSS 像素计算，宽、高分别为 `W`、`H`，视窗左上角为本节屏幕坐标的原点。向右间距为 `0.05 × W`，向下间距为 `0.05 × H`。间距指两张卡片外框边缘之间的空隙，不是节点中心之间的距离。

设焦点卡片在屏幕坐标中的左上角为 `(x, y)`、宽高为 `(w, h)`，新卡片初次显示的屏幕宽高为 `(nw, nh)`。先确定外观下的卡片尺寸，再计算新卡片左上角：

| 情况 | 新卡片屏幕左上角 |
| --- | --- |
| 向右 | `(x + w + 0.05 × W, y + (h - nh) / 2)`，与参照卡片垂直居中对齐 |
| 向下 | `(x + (w - nw) / 2, y + h + 0.05 × H)`，与参照卡片水平居中对齐 |
| 无焦点 | `((W - nw) / 2, (H - nh) / 2)`，保证新卡片中心位于视窗中心 |

页面中的图画布可能有自身偏移、平移和缩放。必须将上述屏幕位置通过当前画布变换的逆变换换算成图坐标，不能把屏幕像素直接当成图坐标。常规平移缩放下，若画布在页面中的偏移为 `(cx, cy)`、平移为 `(tx, ty)`、缩放为 `s`，则图坐标为 `((left - cx - tx) / s, (top - cy - ty) / s)`，其中 `s > 0`。

例如视窗为 `1200 × 800`，参照卡片为 `(200, 160, 240, 120)`，新卡片屏幕大小为 `200 × 100`：

| 情况 | 计算结果 |
| --- | --- |
| 向右 | 间距 60，新卡片左上角 `(500, 170)` |
| 向下 | 间距 40，新卡片左上角 `(220, 320)` |
| 无焦点 | 新卡片左上角 `(500, 350)`，中心为 `(600, 400)` |

新建候选只计算一次。后续视窗变化不重新套用 5% 或居中规则，但实际尺寸变化需要重新检测碰撞。最终落点可以位于原视窗之外，不为了塞入原视窗而重叠，也不触发整图排版；有碰撞时按 L4 修正候选。节点获得编辑焦点后，再按 L7 平移观察视野使其可见，不为居中再次修改最终图坐标。

#### 焦点快照与命中

工具栏形状按钮在原生按钮抢占焦点之前捕获应用中的节点编辑焦点。有节点焦点时先处理必要的编辑收尾，再对仍有效的目标换形，并将节点编辑焦点交回同一节点；目标因空标题收尾被删除时终止本次换形，不补建节点或恢复失效焦点。无节点焦点时才进入下面的新增流程。批量选集不是单节点焦点，不执行批量换形；一次点击只能走一个分支。

通用新增命令按以下顺序在内存中完成，复制与换形都不调用这套默认标题和焦点连线流程；既有有焦点新增的候选和自动连线规则保留，本轮不为其另增页面入口：

1. 调用方捕获触发瞬间的原焦点节点标识、参照卡片屏幕外框、视窗尺寸和画布变换；形状工具只从无节点焦点的分支进入这套新增流程，同一操作只消费一次快照，不复用历史选中节点或额外添加新建快捷键。
2. 对旧焦点节点执行一次编辑收尾；标题交换与删除规则保持不变。若旧节点被删除，位置仍使用刚捕获的外框，但不保留以它为端点的关系。
3. 分配节点标识，在源文本节点序列末尾创建新节点。形态由调用方提供，通过形态类名引用外观；无明确选择的通用新增采用技术默认圆角矩形，不创建业务类型字段。标题一次性设置为 `const DEFAULT_NODE_TITLE = '新节点'` 的值，卡片文本、笔记与出向列表为空；不复制旧节点文本。实际进入新增分支的五种形态沿用相同的标题、焦点与连线规则。
4. 按快照计算候选图坐标，测量新节点并执行必要避让，再提交完整节点。原焦点收尾后仍存在时追加指向新节点的边，否则不连线；不通过置顶让新节点覆盖已有节点。
5. 清空批量选集，将编辑焦点交给新节点，原生输入焦点放在标题输入框，进入纯文本编辑；按 L7 将新节点的操作区域移入视野。跟随发生在候选计算与避让之后，不重新使用新视野计算创建位置。工具栏该次点击的后续处理不能再次清空新焦点；普通节点外点击仍按原规则收尾并取消焦点。

新节点在获得焦点的同一操作中以非空标题创建，初始状态即可保存，不在挂载后另行补标题。上述过程不写硬盘。若用户随后清空标题草稿，失焦或手动保存前再按正常规则收尾；草稿标题与卡片均为空时删除节点及其关联边，其他节点保留。

普通模式点击命中当前无重叠的节点。文字和编辑控件属于同一节点，非交互连线装饰不能截获卡片点击；选中边的端点控制点可以优先启动改接，不启动节点拖拽。建边模式的卡片点击只取端点，批量选择使用独立状态，不设置遮挡穿透选择或层级调整。

候选位置、未完成手势或旧文件可能暂时带有碰撞数据，但不能作为已提交的可见画面。逻辑在绘制前完成当前轮的尺寸测量与避让；测量或计算未完成时保留上一帧合法画面，不先显示交叠的卡片再等待修正。具体避让算法和刚性选集规则见[局部避让技术草案](logic.md#局部避让与几何有效性)。

#### 位置的源文本记录

节点用 `data-x`、`data-y` 保存卡片左上角的图坐标；两者为成对的有限十进制数，允许负数和小数，不接受空串、单位后缀、`NaN` 或无穷值。坐标按缩放为 1 时的尺度记录，不按屏幕像素取整或按视窗百分比保存。

取消 `data-z` 及其他节点叠放顺序字段。若旧文件含有 `data-z`，读取时将其作为废弃可选属性提示并排除，保留节点其他有效数据；它不参与碰撞处理、选中、排序或保存。CSS 内部用于卡片、连线和工具控件的绘制层次不构成文档层级功能。

坐标可在原始输入中省略。任一轴缺失时，按既定规则为该节点生成一对初始候选，不保留孤立的另一轴值；完整有效数值直接作为候选，包括 `(0, 0)`。已有数值但格式错误仍报告诊断，不以随机数掩盖错误。

缺失位置仍使用 `const MISSING_POSITION_RADIUS = 5`：取独立均匀随机数 `u`、`v`，令 `r = 5 × sqrt(u)`、`theta = 2 × PI × v`，得到 `(r × cos(theta), r × sin(theta))`。这一圆域仅约束初始候选。测量保留节点后统一检查碰撞，必要时移动候选或碰撞邻居；最终有效位置可超出半径 5，不能反复抽样期待自然消除重叠。

手动保存为有效节点写入最终坐标，包括用户动作和独立自动避让导致的变化。重新打开时，在相同尺寸和无碰撞条件下坐标保持不变；若卡片状态、字体、资源或外观导致新碰撞，则局部修正，不自动收拢已释放的空间。未保存的修正不会追写硬盘。

批量移动及复制对选集使用共同位移，不能为避让拆散选中节点；必要时允许局部调整碰撞邻居。源码节点与边的排列顺序不作为叠放数据，不因避让而重排；边标识、方向、说明和连接位置均保持，路径按最新坐标重新计算。

静态 HTML 校验可检查坐标字段与标识，但没有真实 CSS 尺寸时不能确认几何无重叠。浏览器与几何验证入口须使用相同的实际占用外框完成碰撞检查；普通只读字数工具不承担此结论，也不改写位置。

### 统一删除操作

主动删除和失焦收尾调用同一删除函数，输入包括待删除节点的稳定标识与操作来源。失焦路径先执行标题与卡片文本交换；只有交换后标题仍为空，才进入自动删除流程。主动删除记录完整的可撤销变更；空标题自动删除不记录恢复项，并使能够复活该节点或关联边的旧历史失效，具体见[逻辑撤销接入](logic.md#用户操作记录与撤销接入)。

节点有焦点时的 Delete 直接进入主动删除路径，不能先按字符删除处理或用标题交换抵消主动删除。边有焦点时的 Delete 调用独立的关系删除，只移除这一条边，不复用节点删除流程。

1. 从完整内存文档收集所有以目标为起点或终点的边标识，包括重复端点的不同边及自环；同一条边只删除一次。
2. 删除目标节点的 `article` 及其出向关系列表，并从其他节点的 `ul.links` 中移除所有指向目标的关系条目。一个条目被删除后不保留空的 `li`；节点没有出向关系时保留空 `ul.links`。
3. 保持其他节点的标识、三部分文本、Markdown 内容和外观引用不变；保持其他边的标识、起点、终点、连接位置、显示文本及相对顺序不变。不沿可达关系继续删除节点，不提升或重新挂接其他节点。
4. 节点与关联边的移除作为同一次内存更新完成，再更新派生索引、编辑焦点和画面，避免中途校验尚未清理的端点；不重新排列剩余节点。只清除指向已删除对象的界面状态；重复收尾发现目标已不存在时不再删除其他对象。
5. 完成后校验标识、字段与端点完整性，不检查树状拓扑；回路、多个入边、孤立节点或零节点均不是错误。只有用户手动保存才写入文件，删除动作本身不另行保存。

“孤儿”不作为新节点类型或持久化标记。没有入边或没有任何边都是合法结构；指向不存在节点的边仍是格式错误，必须与合法的孤立节点区分。首版删除后保留其他节点坐标，不为整理画面补建连线或虚拟父节点。

### 卡片展开的逻辑接入

每次打开或刷新文件，将所有节点的内存展开状态初始化为收起并使用源文本记录的收起形态；完成尺寸测量与局部避让后自动调整视野，使全部有效节点可见。新建节点也从收起状态开始，获得编辑焦点不自动展开；查找命中同样不自动展开。源文本保留三个字段和Markdown 内容：收起时只渲染标题的非图片内容及完整卡片内容，不挂载笔记预览；展开后标题区、卡片内容、笔记按顺序呈现。图片的挂载由区域与展开状态共同决定。

外观定义一组统一圆角矩形的固定展开宽高，五种收起形态共用；具体像素值在外观实现时确定。宽高按缩放为 1 时的图坐标尺度定义，画布缩放只改变屏幕显示大小；不根据文字长度、编辑／预览切换或视窗尺寸生成另一档展开尺寸。展开时标题区与正文滚动区分开：标题区固定在卡片顶部，正文区按卡片内容、笔记顺序滚动，卡片内容不固定。标题自身过长时可在固定标题区内独立滚动，不挤掉正文的可用区域。圆形按钮固定在卡片右上方，持续可操作。标题栏靠右另显示当前收起形状的小轮廓图标与名称；该标识与可滚动标题文本分开，由形态派生，不可点击，不生成内容截图或新增持久化字段。

收起形态为可见的标题文字及卡片内容提供溢出滚动，不能将未显示到的卡片内容直接裁掉或替换成摘要。图片“完整渲染”表示正常呈现内容，不用仅有名称或图标的占位代替；超出当前视野仍可通过滚动访问。具体宽高、各区高度和内容缩放交由外观实现，内部内容不得撑破固定的展开外框。

编辑状态下三个字段仍显示纯文本源码；收起标题中的图片标记可以作为源码编辑，但不生成图片预览。区域可见性不改变保存内容、文本限额或标题判空；标题只包含图片源码时，收起预览可以暂不呈现该图片，不能因此把节点当作空标题删除。

右上方圆形入口使用原生按钮，提供明确的展开／收起名称与当前展开状态。技术交互默认复用同一按钮：收起时点击展开，展开时点击收起。按钮属于该节点内部，使用统一的节点焦点逻辑；已经在编辑同一节点时，点击按钮不触发节点失焦收尾。收起正在编辑的笔记前先将最新输入保留在内存，并把原生输入焦点移到该节点仍可见的编辑区域，保持节点编辑焦点。

鼠标长按的技术接入约定：

1. 使用 TypeScript 常量 `const CARD_EXPAND_HOLD_MS = 1000`。鼠标主键命中卡片并按住满 1 秒且手势有效时展开；不足 1 秒不展开。同一次按住最多触发一次，已展开卡片长按保持展开。
2. 长按与拖拽共用手势判定；位移达到统一拖拽阈值后取消长按，转为既定的仅位置拖拽。鼠标松开、离开目标卡片、手势取消、窗口失去焦点或节点被删除时清除等待状态，不能在后续操作中迟到展开。
3. 输入框、按钮、链接和滚动条按各自交互处理，不同时启动卡片长按计时；文本选择或内容滚动开始时也取消长按。圆形按钮点击与长按入口不会叠加执行。
4. 长按识别成功时，通过统一焦点流程选中目标节点再展开；长按结束后的单击事件只消费一次，不重复切换展开状态或触发另一次节点收尾。单纯获得焦点、滚动笔记或切换内部控件不改变展开状态。

展开或收起先更新当前外框并检测碰撞；无碰撞时保持位置，有碰撞时按 L4 保持局部范围内无重叠，可以移动当前卡片或邻居，再更新路径。用户触发的避让与展开收起作为一次操作撤销。长笔记滚动本身不改变外框、节点位置或画布，不通过置顶解决遮挡。

不设置子树或分组折叠入口、运行时状态及持久化字段，也不沿任何边隐藏关联节点。有向连接不附带树状拓扑限制、内置归属语义或首版自动排版行为。

卡片展开与内部滚动只在内存中维护，不写入源文本；保存保留完整内容、当前收起形态与避让后的坐标，不保存展开外框或形状标识。重开时全部收起，按实际外框检查碰撞；无冲突不移动，有冲突局部避让，不自动回填此前展开产生的空隙。

### 文本存储与预览建议

三个文本字段保存用户输入的 Markdown 与 LaTeX 源码，仅以文本节点写入 HTML，序列化时转义 HTML 特殊字符。不能将字段源字符串直接作为 HTML 标记插入。Markdown、图片及内联和块级公式的预览作为显示结果生成，不用渲染结果替换原始文本。

节点三个字段的上限分别为 1024、1024、32768 个 Unicode 码点，连线说明上限为 1024。对 HTML 解码后的源字符串计数；节点字段中的 Markdown 与 LaTeX 标记、连线说明中的所有普通字符都计入长度，不按 HTML 实体长度或预览结果计数，也不使用 UTF-8 字节数或 UTF-16 代码单元数代替码点数。

例如，HTML 中的 `&amp;` 解码为一个 `&`，计一个码点。技术上统一将 CRLF 和 CR 换行转换为 LF，再计数与保存；换行归一化本身保留其余缩进、空格和空行，不裁剪正文或执行 Unicode 归一化。用户粘贴超限时仅截取本次粘贴前缀，读取 Agent 写入的超限字段时则按整个字段的上限硬截断；已满足上限的文本保持不变，保存时不再次裁剪。空文本判断只用于判定，不改变保存的文本。生成字段元素时，不把外层 HTML 的排版缩进插入字段正文。

内联公式采用 `$...$`，块级公式采用独立行的 `$$` 包围公式内容。使用已选 `remark-math`，保留 `singleDollarTextMath: true` 配置，交给解析器识别两种形式，再由已选 `rehype-katex`／KaTeX 渲染，允许其局部 SVG 符号，不自行用正则替换全文。[数学插件语法与选项](https://github.com/remarkjs/remark-math/tree/main/packages/remark-math)

三个字段使用相同的 Markdown 解析管线，以 CommonMark 为基础，补充 GFM 表格等语法及数学语法。代码块中的公式标记、图片写法仍作为代码文本显示，不重复解析；普通 Markdown 链接也不自动成为图片或图中有向关系。

三个字段均使用可编辑多行源码的 `textarea`。源文本的 `h2.title` 等元素仍只承载原始文本；预览另用可容纳块级内容的容器，不能把表格、段落或块级公式直接塞进只适合标题文本的预览结构，也不能将预览生成的表格保存为字段外的原生 HTML 内容。

### 编辑与预览组件草案

采用原生多行文本控件与 `react-markdown`、`remark-gfm`、`remark-math`、`rehype-katex` 的组合，底层公式渲染继续保留 KaTeX；允许其 HTML 排版中包含局部 SVG 符号。`remark-gfm` 用于落实已确认的表格等 Markdown 内容支持。节点焦点和失焦收尾规则仍由项目逻辑统一控制。

| 职责 | 组件与状态 | 用途 |
| --- | --- | --- |
| 纯文本编辑 | 原生 `textarea` | 三个字段均可编辑多行 Markdown 与 LaTeX 源码，标题也适用 |
| Markdown 预览 | `react-markdown` | 节点失焦并完成收尾后，渲染保留节点的文本 |
| Markdown 扩展 | `remark-gfm` | 支持表格、删除线、任务列表等 GFM 内容 |
| 数学表达式识别 | `remark-math` | 识别 Markdown 文本中的数学表达式 |
| 公式渲染 | 已选 `rehype-katex`／KaTeX，继续保留 | 渲染内联与块级公式，允许局部 SVG 符号；输出不替代 LaTeX 源码 |
| 图片失败提示 | `react-markdown` 的图片组件映射接入项目的 TypeScript 逻辑 | 正常时展示图片，加载或解码失败时显示统一警告 |

2026-10-14 对工作区安装的 KaTeX `0.16.47` 做了有限输出检查：`output: 'html'` 下，`x+1` 未生成 SVG，而 `\sqrt{x}` 与 `\overrightarrow{AB}` 均生成了 SVG。这些 SVG 属于公式内部符号，在恢复的方案中正常允许；不需要为了消除 SVG 替换 KaTeX 或删减公式。该结果仅针对本地版本和这三个输入，不代表新运行时已经实现或其他公式均已验证。移动卡片时，已有公式预览随容器移动，内容未变时不需要每帧重新排版；节点间 SVG 连线由独立的几何更新流程实时跟随。

`react-markdown` 官方文档提供 GFM、数学插件及自定义组件的接入方式；这里复用其 `remarkPlugins`、`rehypePlugins` 和 `components` 扩展点，图片错误显示逻辑由项目补齐。文本组件提供 TypeScript 类型。[组件文档](https://github.com/remarkjs/react-markdown#use)、[组件映射](https://github.com/remarkjs/react-markdown#appendix-b-components)

本编辑与预览模块使用 React 组件，接入时需要相应的 React 运行环境。该选型不决定画布交互、内容渲染和连线路径依赖，也不引入自动排版。实现时由开发方选择互相兼容的版本并锁定依赖，三个文本字段复用同一配置，不把包版本或插件参数列为用户确认事项。

接入时需要遵守以下约定：

- 使用项目维护的节点编辑焦点决定编辑或预览状态，不由单个输入框的失焦事件直接切换。
- 始终使用同一份文本源码，预览组件只消费文本，不反向生成 Markdown 或修改节点内容。
- 长度、判空、失焦交换与删除规则由项目逻辑执行，不能用组件默认行为替代。
- 笔记未展开时不挂载其编辑与预览组件；标题中的图片在收起时同样不挂载，卡片内容中的完整渲染。所有源码及数据仍读取、校验和保存；可缓存未修改文本的预览结果。
- KaTeX 的样式和字体随文档运行资源交付，不在预览时依赖在线下载；由开发方与外壳统一封装并验证离线公式显示，局部 SVG 符号正常保留。[KaTeX 浏览器资源说明](https://katex.org/docs/browser)

### 图片引用与失败预览

SVG 图片不再因格式而一律判定失败；有效的 Markdown 图片引用（包括按既定图片 URL 规则处理的内嵌 SVG 图片）沿用正常加载与预览流程，实际加载或解码失败时才使用固定提示并保留引用。允许 SVG 渲染不改变 L8 的内容语法边界：用户仍以 Markdown 图片语法提供图片，不把原始 SVG 标记直接注入文本字段的预览 DOM，也不增加图片格式转换功能。

普通链接图片使用 `![说明](地址)`，或 Markdown 引用式图片及其定义；内嵌存储在技术草案中采用 `data:image/...` URL，例如 `![说明](data:image/png;base64,...)`。后者是资源编码方式，不是新增 Markdown 语法。三个文本字段里的完整图片标记、地址和内嵌编码均按源码计入长度。

相对地址以原图文件的资源基址解析，由外壳将这一基址传给预览逻辑，不能误用插件代码或临时预览页面所在目录。源文本保存原始相对引用，不在保存时自动改成绝对路径或下载资源；读取能力仍受实际浏览器宿主约束。

图片先经过区域可见性判断，再通过 `components.img` 接入项目组件，监听实际加载与解码结果。收起时不为标题图片或笔记挂载预览或创建占位；展开后恢复正常渲染及失败提示。不把 `alt` 的浏览器默认显示当作固定警告，也不要求先对每个图片地址发送额外探测请求。错误预览统一引用同一个 TypeScript 常量：

```ts
const IMAGE_UNAVAILABLE_TEXT =
  '图片无法显示：此处应有一张图片，但资源已失效或无法加载。';
```

处理约定如下：

1. 每个图片出现位置独立维护加载状态。加载或解码失败、图片地址被宿主拒绝读取时，以常量文本替换该位置的图片预览；不拼接原 URL、节点标题、错误码或底层异常。其他正文与图片继续渲染。
2. 警告只属于预览，不写入正文、引用或字数，不因提示本身标记内容修改，也不自动保存。若资源结果改变外框并触发局部避让，实际坐标变化另行标为待保存；资源失败仍不是正文格式错误，不阻止正常保存。
3. 原始图片引用及替代说明保留。修改图片地址或重新载入预览时重新尝试加载；旧地址的迟到失败事件不得覆盖新地址已成功的结果，也不建立持续重试循环。
4. 内嵌数据无法解码时复用同一警告；所有 Markdown 图片使用同一加载与失败显示逻辑。块级公式、表格和图片仍服从固定展开卡片的内部滚动规则，不自动撑大外框。

`react-markdown` 的默认 URL 转换不会保留任意协议，内嵌 `data:` 图片需要显式接入。技术方案在图片的 `src` 位置增加受控转换：识别图片 MIME 的数据 URL，以及外壳允许访问的图资源地址；其他链接沿用默认转换，不为支持内嵌图片而对全部 URL 无条件放行。空地址或被转换为不可用的地址直接显示常量警告，不尝试加载当前页面作为图片。[URL 转换接口](https://github.com/remarkjs/react-markdown#urltransform)、[默认 URL 转换实现](https://github.com/remarkjs/react-markdown/blob/main/lib/index.js)

图文件的源文本校验检查引用表达是否合规，图片的可达性在实际预览时处理。缺失图片不升级为整张图载入失败；P7 继续只处理源文本本身的结构、字段等错误。资源已失效、离线不可达、读取权限不足等原因在用户界面统一采用上述常量，不推断为文件一定被删除。

### 编辑事件接入

复用已选 React 环境与原生文本控件的事件能力，处理函数使用 TypeScript 编写，不为单击或焦点切换额外引入事件库。

| 入口 | 逻辑调用 |
| --- | --- |
| 普通模式单击节点、边或对象之外 | 判断节点、可交互连线或空白，按类型收尾旧对象；单击节点进入文本编辑，单击边仅选中且说明框隐藏，空白取消焦点 |
| 工具栏连线入口与两次节点点击 | 收尾旧对象并进入建边模式；依次选定起点和终点，分别投影到最近边缘点，完整后新增关系 |
| 双击边 | 保持同一边的对象焦点并打开纯文本说明编辑，不重复处理双击中的单击序列 |
| 拖动边的起点或终点 | 保持边 ID，原子更新指定端及其连接位置；源端变化同步移动出向关系条目，另一端保持不变 |
| 按 Delete | 批量选集激活时删除选集及关联边，否则按单对象焦点删除；来自文本控件仍阻止字符删除，既无焦点又无选集时不误删旧对象 |
| 点击工具栏形状 | 捕获点击前节点焦点；有焦点时只换形，无节点焦点时才调用新增；目标在收尾时被删除则终止换形，不补建节点 |

| 滚动展开内容 | 固定外框内部滚动，不改变节点坐标、关系或焦点；若另有外框尺寸变化，按独立的几何流程处理 |
| 普通文本输入 | 先检查替换后的总码点数，超限则拒绝本次新增；非空标题及合法正文更新内存字段，空标题仅保留在控件草稿，不写硬盘 |

### 输入长度控制的技术接入

所有页面文本修改共用一套 TypeScript 字段更新入口，先计算拟接受的文本，再更新内存文档。使用同一换行归一化与 Unicode 码点计数规则；控件的原生长度选项不能单独承担这一约束。

设字段上限为 `L`，当前控件草稿长度为 `N`，本次选区长度为 `R`，则本次替换可插入的容量为 `C = L - (N - R)`。一般情况下草稿与已接受文本一致；标题被临时清空时按空草稿计算，不按源文本中暂留的旧标题计算。三个长度均按换行归一化后的码点数计，选区是将被替换的部分；不得把控件使用的 UTF-16 偏移直接当作码点索引。

| 修改来源 | 接纳规则 |
| --- | --- |
| 普通输入或替换 | 新增文本长度不超过 `C` 时整体接纳；超过时拒绝整次新增，保留修改前的文本与选区，不先删选区再拒绝插入 |
| 粘贴 | 先将剪贴板文本的换行归一化，再取前 `C` 个码点，替换选区；只裁剪粘贴内容，不裁剪拼接后的整个字段或丢弃原有后缀 |
| 退格、剪切等文本删除 | 接纳删除后的文本，释放可用容量；标题清空仍等到节点失焦或保存前收尾，不即时删除节点；Delete 属于对象删除，不走这一行 |
| 输入法提交 | 组合前的控件草稿和替换选区作为基线；组合结束后按普通输入规则一次接纳或拒绝，不在候选阶段逐字截断；空标题仍只留在草稿 |

例如标题已有 1020 个码点、无选区时，粘贴 10 个码点只插入前 4 个；标题已有 1024 个码点并选中 8 个时，粘贴 12 个码点只插入前 8 个，其他文本保持原样。直接输入或输入法一次提交超出容量的内容时则整体拒绝，不套用粘贴截断规则。

截断使用码点迭代取得前缀，不能按 UTF-16 下标截断而留下半个代理对。Markdown 标记、公式源码、空格和换行同样占容量，不按预览后的可见字符数计算。

输入法组合缓冲区与内存源文本分开，候选中间态可以显示但不被当作已接受内容；提交超限时恢复组合前的控件草稿。失焦或保存前先结束当前组合并执行同一接纳规则，再运行既定标题交换／删除和保存流程，不为组合中的超限候选另设禁止保存状态。

用户操作撤销恢复此前合法的内存文档或已接纳的控件草稿；对于仍存在的节点，空标题只能回到草稿，不能作为有效源文本提交。已经因空标题自动删除的节点与关联边不能借旧草稿或历史快照恢复，未完成的输入法候选也不作为已接受正文恢复。其他页面文本修改入口同样不能直接绕过长度控制。正常编辑流程中不存在等待保存时才处理的超限源文本，保存流程直接消费已接受的内存文档，不增加重复的长度专属拦截、截断或确认步骤。Agent 直接修改图文件不经过本节输入入口，按下一节的字段级硬截断处理，不使用控件选区或剩余容量规则。操作历史与刷新边界见[逻辑撤销原则](logic.md#l2-已确定的撤销原则)，不提供重做。

### Agent 写入限长与检查工具

打开文件或接收磁盘刷新时，在 HTML 与字段边界可可靠识别的前提下，对保留节点的三个文本字段及连线说明执行统一长度处理，连线说明上限为 1024 个码点且不经过 Markdown／LaTeX 解析：

1. 读取 HTML 解码后的 Markdown／LaTeX 源文，按既定规则归一化换行，再按 Unicode 码点计数。
2. 未超限的字段保持不变；超限字段只保留上限数量的码点前缀，超出部分直接丢弃。按码点迭代截取，不截 HTML 文件字节或 UTF-16 代码单元，避免破坏标签、实体或代理对。
3. 硬截断不寻找句子、Markdown 标记、公式或图片编码的完整边界，也不补全被截断的语法；预览继续按已定 Markdown 与图片失败规则处理结果。每个字段单独计算，不在标题、卡片和笔记之间共享容量。
4. 记录节点标识、字段、原码点数、上限与截去数量，再执行其余字段校验。若截断后标题只剩空白，继续报告无效标题，不自动填入“新节点”、挪用后方文本或套用用户失焦删除。

浏览器载入时的硬截断只修改内存文档，保持手动保存才写回的原则。源文件未保存修正时，后续重新打开仍可再次处理同一超长内容；不把这一过程描述为拦截了 Agent 写盘。

Agent 提示词或未来 Skill 必须包含以下明确约定，不能只写容易混淆的“UTF-8 字符限制”：

> HTML 文件使用 UTF-8 编码。每个节点的标题、卡片文本分别最多 1024 个 Unicode 码点，笔记最多 32768 个；每条连线的说明最多 1024 个码点，可为空，只支持纯文本，不解析 Markdown 或 LaTeX。中文通常一个字计一个码点，非 BMP 字符也按码点而非 UTF-16 长度计数。按 HTML 解码并将 CRLF／CR 统一为 LF 后的源文本计数；节点字段中的 Markdown 标记、公式源码、图片地址和内嵌图片编码均占长度。标题必须非空。写入前检查长度；超出上限的字段在页面载入时会硬截断。

字数辅助工具作为逻辑部分的候选命令行入口规划，使用 TypeScript，并与页面共用计数、换行归一化、字段识别及上限定义。当前仅确定职责，不在本轮实现工具或恢复上一轮 CLI 架构：

- 默认只读检查指定 HTML 图文件，输出节点三个文本字段及连线说明的对象 ID、字段名、实际码点数、上限与超出数量；同 ID 对象另带源文位置或出现序号，连线同时标明起点节点。
- 检查原始可识别字段，不先硬截断或删除重复节点再统计，以免把 Agent 写入的问题隐藏掉。
- 提供便于 Agent 读取的结构化结果及通过／未通过的退出状态；无法解析时明确报告，不能当作长度合格。
- 工具不自动改写文件，也不执行随机定位或其他修复。是否调用不影响浏览器载入时的硬截断规则；具体命令名称和参数留给逻辑实现。

### 失焦处理建议

判空应针对 HTML 解码后的字段源文本：没有字符或全部字符为空白时判为空，含有非空白字符时判为非空。判空只负责判断，不因此裁剪或改写原始文本，避免影响 Markdown 缩进、换行及公式源码。

逻辑维护可指向节点或边的对象编辑焦点。普通模式单击决定保持、切换或取消焦点；节点真正失焦时才调用标题收尾，边失焦时只接纳有效说明并退出输入。建边和端点改接采用专门的手势状态，不把取点当成正文编辑；没有原焦点时无需收尾。

同一节点内的文本输入控件之间切换，不等于节点失焦，不能仅因某个输入控件失去浏览器焦点就交换文本或删除节点。节点之间的有向连接不改变单节点编辑焦点规则。节点之外的工具栏和按钮不跳过必要的收尾；S4 形状命令先捕获目标，收尾并换形后可将焦点交回仍有效的同一节点，不能因按钮抢焦点而误新增。

逻辑维护标题控件草稿与已接受的源文本标题：非空且未超限的输入可更新源文本；清空或仅有空白时只更新草稿，源文本仍保持上次非空值。输入长度按当前控件草稿计算，不能因源文本暂留旧标题而错误占用新输入容量。失焦或保存前先判断草稿是否需要与卡片文本交换，再判断是否删除节点；交换或删除原子完成，不向源文本提交空标题。

手动保存前完成当前草稿的收尾处理，再执行文档校验与序列化；不能因为源文本还留着旧标题而跳过用户已经清空标题的意图。保存按钮与键盘保存等不一定自然触发失焦的操作，统一接入下述保存流程。

该流程只修改内存中的文档，不自行触发硬盘写入。节点删除调用统一删除操作，仅清除目标和全部入边、出边；所有有向图都保留剩余节点和关系，不因出现多个根或孤立节点自动重接。

### 手动保存与文件写入方案

初期采用 File System Access API，由同一套 TypeScript 逻辑将内存中的文档写回 HTML 文件。在支持该接口且允许文件授权的桌面 Chromium 环境中，由浏览器处理操作系统差异；文件写入本身不需要后台进程，也不预先为 Windows、macOS、Linux 分别实现保存逻辑。

文件访问与写入按以下方式接入：

按[外壳 S2](shell.md#s2-已确定的文件操作)，新图先在内存中编辑，首次手动保存时才选择文件位置；已有文件保持原位保存。没有另存为功能，底层保存位置选择能力仅用于新图首次保存，不据此增加副本入口。

1. 打开其他图通过 `showOpenFilePicker()` 获取文件句柄，成功载入后在当前页面替换图；新图首次手动保存时通过 `showSaveFilePicker()` 选择目标并获取句柄。新建时不选址、不写临时文件；已有图后续保存复用当前句柄，不提供另存。直接在浏览器中打开 HTML，不等于页面已经获得该文件的写入句柄或授权。
2. 复用当前目标文件的句柄，在需要时请求写入授权。选择器和授权请求须满足安全上下文、用户操作及页面嵌入方式的限制；需要这些操作时，应在保存按钮或快捷键触发的用户操作中及时发起，避免先执行耗时异步工作而丢失用户激活状态。
3. 保存按钮与键盘保存调用同一流程：完成编辑收尾、当前外框测量与必要局部避让，校验有效模型，序列化全部有效内容和最终坐标，由外壳组合必要文档结构、格式标识、固定版本资源引用及源图后写回 HTML。公共代码、CSS、字体、工具界面、错误原文、废弃层叠字段与预览 DOM 不输出，合法隐藏内容仍保存。不等待所有远程图片成功加载；按当前已知外框保存，晚到资源若改变尺寸，再独立避让并留待下次保存。
4. 写入并成功关闭写入流后，才能确认保存成功；取消文件选择、拒绝授权或写入失败不得标记为已保存。载入警告不阻止保存有效数据；本次保存不携带原异常内容。磁盘任何变更仍触发强制刷新并丢弃未保存编辑，包括本次手动保存造成的变更。

新图首次选择位置取消时继续保留内存草稿。目标确定后，外壳按目标与当前公共资源的相对关系生成引用；不能借用之前打开的图作为保存目标或图片基址。同页打开另一图时同步切换当前文件身份、资源基址和版本、写入句柄及变更检测对象；取消或读取失败不能伪造空图并覆盖当前内容。S5 暂不展开，不新增文件名／未保存状态展示或自定义离开确认；文件选择、授权与已定保存流程继续保留，不把 S5 当作切换文件的前置决策。

上述接口与权限约束参考 [Chrome 文件系统访问说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)和[文件系统访问规范](https://wicg.github.io/file-system-access/)。现有图的选择、授权、原位写回与改盘重新读取已在 alpha.2 中实现，并于 2026-10-16 在本机 Chrome、Codex 完成最小流程验收；新图首次选址等完整 S2 能力仍待完成。不代表所有采用 Chromium 的应用都向内嵌页面开放相同能力。

Chrome 与 Codex 的当前最小流程结果见[验收记录](../../verification/html-milestone/README.md)。后续逐步验证更多 Agent 应用及完整文件操作，只有发现实际能力差异时才补充对应适配。当前不预设多套保存后端，也不把本机最小流程的结果扩大为所有版本、操作系统或 Agent 应用的兼容承诺。

磁盘变更检测与强制刷新单独验证。alpha.2 的两次真实外部改盘在两个宿主中分别通过，未保存草稿及历史清空亦经人工观察确认；自动刷新复用 live 文件句柄并重建整个编辑会话，具体接入见[外壳保存与文件会话](shell.md#保存与文件会话)。后续实现仍须满足[架构主要原则](architecture.md#主要原则)，不能仅由写入接口存在推定监听可用。S1 的完整打包和更多文件场景继续按外壳草案落实。

### 预期规模与性能分析

按[架构中的使用规模](architecture.md#产品方向)，主要考虑 10–200 个节点的创作场景，1000 个及以上节点不纳入当前支持目标或性能验收范围。先完成功能，再通过实际运行分析并优化；当前不要求先确定深层树或大规模节点的专门优化方案，也不新增节点数硬性校验上限。

以下仅记录结合产品交互推测的卡顿原因，不表示现有实现已经发生这些问题：

| 出现卡顿的操作 | 后续分析时可检查的原因 |
| --- | --- |
| 打开图文件 | 一次处理大量文本、图片和公式，或对尚未展开的笔记也生成预览，使初始化工作过重 |
| 输入文字 | 每次输入都重复校验整份文档、解析所有节点的预览或重复测量整张画布的卡片尺寸 |
| 拖拽、平移和缩放 | 高频交互中反复计算无关连线或更新大量页面元素；首版本身不执行自动排版 |
| 展开卡片 | 笔记内容集中生成，卡片尺寸变化引起重复测量、浏览器页面布局和连线更新；逐个修改样式并读取尺寸也可能重复触发页面布局 |
| 手动保存 | 全文序列化、写入，以及按既定原则强制刷新后的解析、预览、尺寸测量和浏览器页面布局叠加；需分别测量，不能直接认定是硬盘写入慢 |

节点数只是影响因素之一，还要看每个节点的内容复杂度、同时显示多少内容，以及一次操作触发多少计算。一个图节点可能生成多个页面元素；同样数量的节点，仅有短文本和包含长文、图片、公式时的开销不同。

浏览器主线程中的长时间计算和重复布局可能推迟输入响应与画面更新，参考 [web.dev 长任务说明](https://web.dev/articles/optimize-long-tasks)和[布局开销说明](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)。后续在实际目标宿主中测量打开、编辑、拖拽、展开和保存等操作，再决定是否需要进一步缓存、局部更新或其他优化。

### 校验流程与诊断

打开文件或接收磁盘刷新时，先检查 HTML 语法、格式版本与可识别的节点边界，再执行已明确的分类处理，最后校验处理后的源文本结构、字段和业务约束。浏览器能够构建 DOM 不等于原文格式正确；保留语法诊断，不把浏览器自动修复后的树当成原文件无误的证明。不把任意不明结构当成空图，也不对未定义的异常猜测内容。

分类处理顺序如下，用于页面载入路径，底层规则由 TypeScript 逻辑统一维护；只读字数检查入口仅复用字段识别与计数规则，不运行这些修复或截断步骤：

1. **节点去重。** 按源文本中图容器及其直接节点的文档顺序检查，记录每个非空节点 ID 首次出现的元素。后续同 ID 节点按元素身份删除，连同自身文本、Markdown 内容和出向关系列表一起移除；不合并到第一个节点。即使后出现节点内容更完整，也不替换第一个。
2. **建立保留节点索引。** 只为保留节点建立索引。不能先用按 ID 覆盖的映射读取节点，否则会错误保留最后一个。节点去重不能调用常规的“按节点 ID 删除并清理所有入边”操作，否则会误伤第一个节点及指向它的连线。
3. **取消无目标连线。** 扫描保留节点的关系列表；对可解析的本图目标引用，若目标不在当前图的保留节点集中，删除该条边及其列表项。指向仍存在的重复 ID 则解析到第一个节点并保留。不创建占位节点，不改指其他目标；无法解析的地址等其他错误仍报告诊断，不执行边类型校验。
4. **生成坐标候选。** 为缺少完整位置的节点在原点半径 5 内生成候选，完整有效坐标直接保留为候选；废弃层叠属性排除，不参与位置计算。最终几何处理在有效节点与边确定后进行。
5. **字段硬截断。** 按 HTML 解码、换行归一化和码点计数规则处理超限字段，标题、卡片及连线说明保留前 1024 个、笔记保留前 32768 个码点；已有合规字段保持不变，不执行语义补全。
6. **构建有效数据并集中警告。** 记录去重、取消连线、坐标补齐与截断结果；无法自动处理的错误进入右上方警告栏。必需标识、标题无效的节点不进入有效数据，无法解释的可选内容排除但不阻断同节点的其余有效内容；不填入占位标题或猜测丢失内容。
7. **清理有效数据的关系。** 按最终有效节点集排除无效端点边，保留有效标识、说明及连接位置；不重接、不创建替代节点，废弃边类型属性不输出。
8. **测量与局部避让。** 按默认收起状态和实际外观测量有效节点，处理全部碰撞后再显示可编辑结果。重叠不使节点或边被排除；更新后的坐标先保留在内存，等待手动保存。

处理先作用于当前载入产生的内存文档，只有手动保存才写回图文件。对同一份已处理的内存文档再次检查，不应重复随机定位或继续删改；原文件未保存时重新载入，可按同样规则重新处理。文件被删除或无法读取属于文件访问失败，不能凭分类处理重建成一份空图。

用户编辑中清空标题的临时状态只存在于控件草稿，不进入内存源文本；超限内容在输入阶段拒绝或按粘贴规则截断。手动保存前完成草稿收尾，校验并序列化有效数据；原始输入中的错误只形成警告，不作为原文拼回输出。读取与检查仍覆盖隐藏笔记、独立节点和全部关系，不能因不渲染就忽略诊断。Agent 改写的图文件载入时执行字段硬截断，其余无法处理内容排除。树、森林、回路、多个入边、孤立节点及空图均支持保存。

诊断包含错误类别、可识别的节点标识、字段名称与原因；源文位置或出现序号只用于定位问题，不承担原文回写。界面和验证脚本复用基础规则，按入口区分只读检查和载入处理。载入路径执行既定修复和超限截断，无法处理的部分集中警告并从有效模型排除；仍不随意裁剪已经有效的正文或重命名有效节点。

#### 右上方警告与有效内容保存

逻辑输出有效数据模型与诊断列表，外壳将无法自动处理的错误集中展示在网页右上方警告栏。有效部分照常显示、编辑和保存；错误内容不进入保存模型，也不需要为其维护原文副本、源文范围映射或局部补丁。

按[外壳 S3](shell.md#s3-已确定的查找与警告布局)，警告栏是右上方常驻的横向区域，无警告时显示空状态；查找框在其下方按需打开，关闭查找不隐藏警告。此处更新的是旧纵向警告侧栏的展示位置，不改变诊断范围或有效内容保存规则，也不把警告栏、空状态或查找控件写入图文件。

保存从有效模型生成完整图文件，包含合法的图信息、全部有效节点及其内容、Markdown 源码和有效连线。当前隐藏的笔记、标题媒体及其他有效内容仍完整保存。错误原文、警告文字、无法解析的片段和被排除节点的关联边均不输出，不通过附加 HTML 区域或其他存储保留错误内容。

原始文件中不存在的目标，以及存在但被判定无效而排除的目标，都不能出现在有效关系的端点中；前者取消无目标连线，后者排除相关连线，可在诊断中区分原因。若有效图容器保留但全部节点被排除，结果按既定空图规则保存，不创建占位节点。文件无法读取或图结构完全不可识别时，继续在警告栏说明原因，不猜测缺失节点或关系。

只有手动保存才覆盖硬盘文件，载入警告本身不触发写盘。保存后按既定原则刷新，从新文件恢复有效内容并重新计算警告；此前因已排除内容产生的警告不应再次出现，仍可能存在图片资源加载失败等运行时警告。无需恢复被舍弃的异常原文或此前丢弃的编辑草稿。

载入自动去重、取消无目标边、补齐位置、截断与排除无效内容不进入用户操作历史，不能通过撤销找回异常原文。合法内容被用户主动删除后可在本次会话的撤销记录中临时保留；记录不写入文件，刷新后清空，也不能跨手动保存后的刷新恢复。

### 校验项

| 校验项 | 检查内容 |
| --- | --- |
| 格式版本 | 完整 HTML 的格式标识属于当前支持版本，文档使用 UTF-8 编码 |
| 平级节点结构 | 每个图的节点都是 `section.map` 的直接 `article` 子元素，不通过嵌套表达归属，不要求通用图具有共同根节点 |
| 节点与关系标识 | 检查文档范围的 ID 冲突，重复节点先保留第一个；有效模型使用唯一 ID，无法处理的冲突对象进入警告栏提示并从保存结果排除 |
| 重复节点处理 | 仅删除后出现的同 ID 节点元素及其自身内容、出向关系，不合并或重命名；指向该 ID 的合法入边仍连接第一个节点 |
| 通用图与形态 | 图容器、节点和边不输出 `data-type`；节点只按外观类名选择形态。旧类型属性仅排除属性，不排除其他有效内容；外观异常按默认圆角矩形外观处理 |
| 节点字段 | 每个节点恰有一个直接 `h2.title`、`div.card`、`div.notes` 字段与 `ul.links` 列表；无出向关系时列表为空 |
| 关系条目 | 边位于源节点的直接关系列表中，每个直接 `li` 含唯一直接 `a`；最终两端必须属于有效节点集，否则排除；其余有效边的 ID、文本、连接位置和顺序保持不变 |
| 完整关系模型 | 独立节点、多个入边或出边、平行边、有向回路和自环均可完整读取和保存；不能只遍历某个起点可达的部分 |
| 拓扑不设树限制 | 不按内容场景强制无环、单父、连通性或根节点数量；编辑和显示所需的结构分析不改变源文本有效性 |
| 无内置边类别 | 边不保存 `data-type`，不回填默认类别，不按说明关键词或外观执行分类；读取旧属性只排除属性，保留其余有效的边 |
| 空图 | 保留有效图容器与文档信息，允许零节点、零关系；保存和重新打开不自动创建占位根节点 |
| Markdown 内容边界 | 图片与表格只位于三个文本字段；不接入字段外的图片、数据表、成员表、时间或笔画扩展，图片资源暂不可达仍只影响预览 |
| 结构与外观 | 结构类名在更换外观后仍保留，外观名称不占用结构类名，外观类名不表示业务类型 |
| 空文本约束 | 空字符串及仅含空白的文本统一视为空；编辑收尾后的有效节点标题非空，卡片文本和笔记文本允许为空 |
| 文本长度 | 标题、卡片文本与连线说明分别不超过 1024 个 Unicode 码点，笔记文本不超过 32768 个 Unicode 码点 |
| 连线说明 | 只显示纯文本，不解析 Markdown／LaTeX 或语义关键词；允许空文本，说明截断或清空不改变边 ID 及端点 |
| 连线外观与说明框 | 默认贝塞尔，创建时可选直角折线或直线；保存原生类名，复制保留。说明框尺寸、沿线路径位置与交叉配色只作派生显示，不生成独立节点或源字段 |
| 连接位置 | `data-start`、`data-end` 可省略；存在时分别为两个 `[0, 1]` 内的有限数；错误属性警告并排除，保留其余有效关系；显示投影到实际轮廓 |
| Agent 字段硬截断 | 载入时先解码、归一化换行，再对每个超限字段取码点前缀；不截 HTML 或 UTF-8 字节，不破坏代理对；恰好等于上限不截断，处理后再次运行结果不变 |
| 截断后的有效性 | 硬截断后仍检查标题非空等规则；不为保留 Markdown、公式或图片语法而超额保留，也不自行补全源码 |
| 字数工具 | 只读检查原图文件，报告实际长度、上限和超出数量；不先截断后报合格，不执行节点去重、坐标补齐或写盘，与浏览器复用同一码点口径 |
| 普通输入限长 | 拟写入结果超限则拒绝本次新增，原文本和选区不丢失；满额时仍能删除、剪切或进行不超限的选区替换 |
| 粘贴截断 | 按扣除选区后的容量截取粘贴内容前缀，保留原有前后文；覆盖满额、部分容量、选区替换、换行及非 BMP 字符，不截断代理对 |
| 输入法组合 | 中间态不写入内存源文本，组合提交按普通输入规则接纳或拒绝；失焦及保存先完成组合处理，不提前执行空标题删除 |
| 不设超限保存流程 | 已接受的用户文本始终不超限，不存在专门的超限禁存、保存时裁剪或要求用户先修复长度的流程；Agent 直接改写的图文件本身仍受校验，不表示节点可加载外部文档正文 |
| 对象编辑焦点 | 普通模式单击节点即编辑，单击边选中且说明框隐藏、双击才显示并编辑说明，退出编辑隐藏；切换对象先收尾，同一对象内部保持焦点；建边取点不进入正文编辑 |
| A3 临时外观 | 统一焦点粗描边，默认蓝色；框选仅节点，全部选中节点有描边但不同时编辑；查找只突出当前定位对象，无悬停或额外过程提示；所有状态均不写入源文本 |
| 隐藏说明的完整性 | 未显示的边说明仍可保存、计数与查找，隐藏框不参与避让；重新双击显示原有效文本，空说明也可输入，不把隐藏当作删除 |

### 技术落实与验证职责

当前内容范围和通用产品规则已确定，按上述草案实现格式、标识、文本处理、事件接入及校验，不为被排除的内容场景预增字段。首版只使用默认主题，已有节点形态与样式引用保持，不增加主题选择偏好。S1 的资源封装方向已确定；依赖版本、具体打包、文件句柄恢复和磁盘变更检测由开发方在逻辑与外壳中完成接入和宿主验证，不要求用户选择底层接口或算法。

技术草案不代表运行能力已经完成。File System Access API 写回与磁盘变更强制刷新分别验收；先验证 Chrome、Codex，再按实际差异适配更多 Agent 应用。功能完成后按 10–200 个节点的目标场景分析性能，只有测得瓶颈时才增加针对性优化。

当前[外壳产品问题清单](shell.md#未确定的产品问题)已按首版范围收敛；后续仅有新增产品取舍，或验证发现宿主能力无法满足已定要求时，才回到产品层讨论。既定逻辑与内容范围不因打包方式重新展开，技术细节继续在源文本、外观、逻辑和外壳四部分内落实，不新增顶层架构层。
