# 外壳设计草案

更新日期：2026-10-16。

本文件属于[四部分架构](architecture.md)中的外壳部分，分别记录产品设计与技术草案。首版产品设计基线已齐备：S1–S4 已确定，S5 暂不展开，S6 仅使用默认主题且不提供主题选择入口。当前 alpha.2 已完成最小文件流程的运行包及本机 Chrome、Codex 验收；完整外壳功能与其他场景仍按本稿推进，范围见[工程记录](../../app/README.md)。

## 产品设计草案

### 职责与边界

外壳将源文本、外观和逻辑组织成用户可以打开、操作和保存的页面。Agent 直接编辑图的 HTML 源文本；用户使用的界面由外壳在运行时组织，不要求 Agent 通过界面操作修改图。

| 职责 | 外壳负责的内容 |
| --- | --- |
| 页面组装与启动 | 加载公共资源，读取当前图源文本，调用逻辑完成校验、初始化与首次显示 |
| 界面组织 | 安排画布、工具栏、查找工具和右上方警告栏，向逻辑提供实际可用的画布范围 |
| 功能入口 | 将按钮、菜单等用户输入交给既定操作，不另行实现一套节点、关系或撤销规则 |
| 文件与宿主接入 | 衔接文件选择、授权、读取、写入及外部变化通知；具体校验和序列化沿用逻辑 |
| 资源与主题组织 | 加载对应版本的外观和运行资源，提供图文件与公共资源各自的基址，统一使用默认主题 |
| 状态与诊断展示 | 呈现有效文档及逻辑返回的警告，接入文件操作结果；查找与警告栏显隐按 S3，功能入口按 S4，S5 状态展示与离开提醒暂不展开 |

这些职责仍归入源文本、外观、逻辑、外壳四部分，不增加新的顶层架构层，也不要求四部分各自成为独立软件包或后台服务。

### S1 已确定的交付与离线使用

**每张图保存为一个简洁的 HTML 文件，只保留源文本和必要的资源引用。外观、逻辑和外壳作为按版本管理的本地公共资源，通过相对路径加载，支持离线使用。**

| 内容 | 保存位置与约束 |
| --- | --- |
| 图的描述 | 保存在图 HTML 中：节点、标识、标题、卡片文本、笔记、边、说明、坐标、连接位置及已有形态和样式引用 |
| 必要文档结构 | 图 HTML 保留 HTML 文档结构、编码与格式标识，以及指向公共资源的少量引用 |
| 外观与运行程序 | 放在公共资源中，包括默认主题样式、逻辑、外壳程序和浏览器运行依赖；不内嵌到每张图 |
| 字体与界面图标 | 必要资源随本地公共资源包提供，不要求首次打开或使用某项功能时联网下载 |
| 用户操作界面 | 工具栏、查找、警告、编辑控件等由外壳在运行时生成，不存入图的源文本 |
| 派生显示 | SVG 连线路径、公式预览、当前焦点、选集及其他临时状态不写回图文件 |
| 正文图片 | 继续使用已定 Markdown 图片规则，不强制下载或打包外链图片；用户已有内嵌图片仍作为正文保留并计入字段长度 |

源文本的判断标准是该信息是否用于描述图；必要资源引用是启动页面所需的明确例外。坐标、连接位置和形态引用继续保存用户制作的结果，具体绘制代码与 CSS 则属于公共资源。Agent 普通改图只需修改源文本，保留资源引用，无须读取或改写公共程序。

公共资源可以被多张图复用，用户无需安装插件即可使用已准备好资源的图。这里的“一张图一个 HTML”不表示该文件自带完整编辑器：第一次向没有资源的人交付时，需要同时提供对应版本的公共资源。完整离线运行不依赖曾经联网形成的缓存，不从 CDN 临时补齐应用依赖。

图文件与公共资源约定相对目录关系，不写死用户目录、磁盘盘符或某台机器的绝对路径。整体移动并保留相对关系时，引用应继续有效；单独移动图文件后，需要保持或重新建立可解析的引用。实际目录名称由技术草案给出，不要求用户逐项决定。

公共资源按版本管理，图引用明确的资源版本。不同版本可以并存，普通打开、编辑和保存不自动改用最新版本；提供新版本不直接覆盖旧版本内容。资源版本与源文本格式版本分别管理，不因更换依赖就自动重写图的格式。

### 延续已有产品规则

- 图仍是通用有向图，所有已定的内容、编辑、删除、撤销、批量操作、局部避让和查找规则保持不变；不恢复自动排版、重做、多用户协作或被排除的内容能力。
- 用户编辑先存在内存，只有手动保存才写盘；Agent 直接修改硬盘图文件。当前图文件的任何磁盘变化强制刷新，丢弃未保存编辑并清空历史，包括手动保存引起的变化。
- 保存只输出有效图内容和必要引用，不保存异常原文、运行时界面或预览 DOM；合法隐藏内容仍完整保存。
- 默认画布为浅灰点阵，图内元素等比缩放且不保证最低可辨识尺寸；工具栏、查找工具和警告栏随主题配色，默认白底黑边，不随图画布缩放。
- 无法自动处理的源文件问题集中显示在右上方警告栏，有效部分继续编辑与保存；图片无法加载时沿用固定警告。读取不到文件不能伪造为空图。
- 文件写回与外部变化检测分别验证；S1 的离线资源约定不等于浏览器已获得文件授权，也不证明任何宿主都已满足保存与强制刷新要求。

### S2 已确定的文件操作

| 项目 | 已确定的产品规则 |
| --- | --- |
| 新建图入口 | 提供新建图功能，创建一份新的通用有向图，不要求选择图类型 |
| 新图起始内容 | 恰好包含一个节点，标题复用新增节点的默认标题，即当前的“新节点”；卡片文本、笔记为空，没有连线 |
| 打开其他图 | 提供入口，用选择的图替换当前页面中的图；不另开一个图页面，也不增加应用内多标签管理 |
| 首次保存 | 新图先在内存中编辑，首次手动保存时才选择文件位置并写入；新建时不先要求选址，不生成临时图文件或自动保存 |
| 后续保存 | 复用该图当前文件进行原位写回；保存产生磁盘变化后仍强制刷新 |
| 另存为 | 不提供另存为功能、入口或同义的另存副本命令，不将其作为保存失败的自动降级方式 |

“一个节点”只约束新建整张图的起始内容，不是节点数量下限。用户删除最后一个节点后仍可保存空图；打开已有空图仍保持为空，不补入默认节点。初始节点没有特殊根节点身份，之后沿用通用新增、编辑和删除规则。

同页替换完成后，当前图、保存目标、图片资源基址、公共资源版本和磁盘变化检测对象都应对应新打开的图。S5 暂不展开，不新增自定义离开确认或自动保存流程；取消选择、读取失败或目标未就绪时仍不误替换当前图，只有提交新图切换时才清理旧会话；磁盘变化导致的强制刷新规则仍不等待确认。

### S3 已确定的左侧工具栏

参考[用户提供的左侧工具栏截图](assets/toolbar-left-reference.png)，只采用左侧工具条的布局与外形，不将中间图表、顶部控件或截图中的其他功能作为项目需求。

| 项目 | 已确定的布局与外观 |
| --- | --- |
| 位置 | 位于页面左侧，靠近视窗边缘并留出少量间距；随界面定位，不随图的平移或缩放移动 |
| 形式 | 竖向窄条工具栏，采用圆角容器与轻阴影，按钮以图标为主、从上到下单列排列；可使用细分隔线组织已定功能 |
| 显示 | 常驻显示，不提供关闭、收起或自动隐藏行为 |
| 与画布的关系 | 工具栏浮置在画布上方，只覆盖自身所在区域；不为它划出一块贯穿全高的实心侧栏。浮置不代表新增自由拖动或停靠功能 |
| 配色 | 延续 A4：首版使用默认主题，工具区域白底黑边；截图的细节颜色不覆盖已经确定的配色原则 |
| 功能范围 | 文件按钮固定在最上方，其下提供形状和连线工具；按 S4 根据节点焦点分发新增或换形。截图中的手绘、独立图片／表格、评论等图标不自动成为本项目功能 |

工具栏的精确宽度、图标大小、间距、圆角与纵向位置由技术草案补齐，不要求逐像素复制截图；保持左侧常驻，不以窗口变窄或图缩放为由自动收起。按钮内容与分组按下述 S4 执行。

### S3 已确定的查找与警告布局

参考[用户提供的查找与上方条带截图](assets/search-warning-reference.png)：下方横向查找框作为查找工具的外形依据，上方原状态条的位置改为警告栏。两条区域位于页面右上方、右侧对齐并上下留出间距，浮置于画布上；警告栏在上，查找框在下，不再采用右侧纵向警告侧栏。

| 区域 | 已确定的产品规则 |
| --- | --- |
| 警告栏 | 始终显示，位于右上方的横向圆角容器中；无警告时显示空状态，有警告时呈现问题位置与原因，不提供关闭或收起 |
| 查找框 | 采用截图中的横向圆角输入条，左侧查找图标与文本输入区，右侧结果数量及关闭按钮；默认关闭，通过查找入口按需打开，关闭后可再次打开 |
| 筛选与定位 | 继续只提供节点／边筛选，不选择时查找全部；仅通过上／下箭头按钮定位上一个／下一个命中对象，不提供点击结果列表定位；只突出当前定位对象，不自动展开或进入编辑 |
| 配色与空间 | 默认主题采用白底黑边；两栏浮置覆盖局部画布，不新增占满右侧或顶部的实心面板，也不随图平移缩放 |

关闭查找框不关闭警告栏或左侧工具栏。截图上方的分享、编辑模式、评论和更多菜单不作为需求；查找框中的附加匹配图标也不扩展已有筛选规则。查找入口按 S4 放在右上角，与警告栏、回原点及缩放控件在同一区域，关闭后仍可重新打开。

警告区域仍承载既定诊断内容，有效部分继续显示、编辑和保存；横向布局不将警告改为仅显示数量，也不改变异常内容保存规则。多条诊断的排版、容器尺寸和滚动由技术草案补齐，不因警告数量增加覆盖整张图。

### S4 已确定的功能入口

| 功能 | 已确定的产品规则 |
| --- | --- |
| 文件操作 | 新建图、打开其他图、保存放入左侧工具栏，始终位于最上方；不提供另存为 |
| 手动建边 | 用户先选择工具栏里的连线工具及所需线型，再依次选起点、终点；未选择线工具不能通过普通节点点击直接创建边 |
| 自动连线 | 既有通用新增节点的自动连线规则继续保留，默认贝塞尔曲线；批量复制仍复制全部关联边并保留已有外观，未指定外观的边按默认贝塞尔处理 |
| 形状工具 | 有一个节点获得编辑焦点时，点击工具栏形状将该节点改为所选形态；无节点编辑焦点时，点击形状创建一个对应形态的新节点。新增与换形互斥，不将一次点击同时解释为两者 |
| 撤销 | 仅通过 Ctrl+Z 或 Cmd+Z 撤销，不提供撤销按钮、菜单入口；仍不提供重做 |
| 复制与删除 | 只提供快捷键，不设按钮或对象操作菜单；沿用 L3 复制与关联边处理，Delete 继续删除焦点对象或节点选集 |
| 缩放 | 右上角提供滑块及当前比例显示；图内元素仍等比缩放，不增加最低可辨识尺寸、恢复 100% 或手动显示全部功能 |
| 回原点与查找入口 | 放在右上角，与缩放控件和常驻警告栏在同一区域；不挤占左侧工具栏的文件操作组 |
| 查找结果定位 | 只通过“上一个”“下一个”逐项定位，分别使用向上、向下箭头按钮；不提供可点击定位的结果列表，也不因输入查找词就自动定位首项 |

形状按钮取决于点击前的节点编辑焦点。对有焦点节点换形时保留其标识、完整正文、笔记和已有边，只更新形态及必要的局部避让；展开节点仍保持统一圆角矩形，仅更新收起形状及标识。批量选集不等同于单节点编辑焦点，不据此增加批量换形。

通用新增节点的默认标题、聚焦、候选位置与焦点自动连线规则不因手动线工具的前置要求取消；但形状按钮的有焦点分支只调用换形，不调用新增。当前形状按钮实际新增时走无节点焦点分支，不另造一个“有焦点强制新增”的按钮或快捷键。Agent 直接编辑源文本不受页面工具选择限制，复制关联边和撤销恢复已有边也不要求先选线工具。

### S5 暂不展开

本轮不再细化文件名展示、未保存标记和主动离开提醒，不把这些内容列为首版必须实现项或继续讨论的前置条件；不新增对应状态界面、自定义离开确认、自动保存或草稿恢复流程。浏览器或宿主自身已有的行为不在本轮调整，也不宣称主动关闭与刷新行为已完成兼容性验证。

既有规则继续执行：用户手动保存才写盘，新图首次保存时选址，取消首次选址保留内存草稿，保存失败不报告成功，打开目标取消或读取失败不误替换当前图；完成同页替换时按 S2 清理旧会话。当前图文件的任何磁盘变化仍强制刷新并丢弃未保存内容，不等待确认。文件选择与系统授权仍按已有接入方案处理。

这是当前范围取舍，不作为以后永远不能增加状态展示或提醒的限制；有新的明确需求时再讨论。

### S6 仅使用默认主题

首版只提供已经设计的默认主题，打开图时直接加载，不提供主题选择或切换入口，也不新增主题偏好保存或自定义样式编辑器。默认主题同时覆盖画布、节点、连线、工具栏、查找框与警告栏。

五种节点形状、三种连线路径外观和交叉边异色继续保留，它们属于默认主题内的外观表达，不是多套主题。源文本已有的形态与样式引用、公共资源按版本加载的方式保持不变；`default`、`basic` 等现有引用不因取消主题选择入口而删除。

未来只有出现明确的多主题需求时，才重新设计相应功能；当前不为其增加页面入口、配置项或首版验收任务。

### 未确定的产品问题

当前首版没有剩余的外壳产品待确认项。S1–S4 与 S6 已确定，S5 已明确暂不展开；开发方按本稿补齐技术参数、模块接入和验证，只有新增产品取舍或实测无法满足已定要求时才回到产品讨论。

## 技术草案

### 公共资源的发布边界

外壳和逻辑继续以 TypeScript 开发，公共资源发布浏览器可执行的 JavaScript；CSS、字体、图标及所需第三方依赖随同发布。使用者不需要安装开发依赖或编译代码，普通改图也不需要重新构建资源包。

优先将运行代码与依赖预先合并成可直接加载的普通脚本，避免本地打开时再逐个进行模块导入或通过网络补齐依赖。离线依赖检查覆盖公式、默认主题样式、字体和图标，不只检查首次打开。必要时字体等可以内嵌于公共 CSS 或程序资源中，仍不进入图 HTML。按引用的资源版本直接加载默认样式，不增加主题枚举、运行时切换器或用户主题偏好存储。

本地 `file://` 页面的跨文件访问会受到浏览器限制，普通外部脚本与模块导入的要求不同；路径存在不等于必然可读取。按目标宿主验证脚本、样式、字体和其他运行资源，不要求用户关闭浏览器安全机制，也不默认恢复上一轮后台读写架构。参考 [MDN 外部脚本说明](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/What_is_JavaScript#external_javascript)与[本地文件来源约束](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy#file_origins)。

### 目录与引用草案

下面仅说明发布结果的相对结构，`1.0.0` 是示意版本，所列资源文件尚未生成：

```text
workspace/
├── runtime/
│   └── 1.0.0/
│       ├── app.css
│       ├── app.js
│       └── assets/
└── maps/
    ├── diagram-a.html
    └── diagram-b.html
```

图文件保留原生资源引用；以下为空图的完整文档形式示意，不是可运行的已发布示例，也不代表新建图的默认内容。S2 规定新图以一个默认节点开始，用户删除该节点后仍可保存此类空图：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <meta name="format" content="mindmap/1">
    <link rel="stylesheet" href="../runtime/1.0.0/app.css">
    <script defer src="../runtime/1.0.0/app.js"></script>
  </head>
  <body>
    <section class="map default"></section>
  </body>
</html>
```

样式与程序引用同一个明确发布版本，不指向可变的 `latest`。公共包记录其支持的源文本格式与依赖版本；已发布版本目录保持内容稳定，升级新增目录并另行处理图的引用，不在普通载入或保存中静默迁移。

资源路径使用相对于图文件的 URL，正确处理路径中的空格等字符；外壳区分图文件基址和公共资源基址。正文相对图片继续按原图文件位置解析，公共包内部字体等按其资源位置解析。不能用修改整份文档的基础 URL 来把正文图片、节点片段链接一并指向公共资源目录。[相对引用解析说明](https://developer.mozilla.org/en-US/docs/Web/API/URL_API/Resolving_relative_references)

### 启动与源文本隔离

1. 浏览器加载图 HTML 及其资源引用，公共启动程序从当前文档读取既定源文本容器和格式标识，不要求再通过网络请求获取同一份图内容。
2. 逻辑按现有规则解析、诊断并建立有效内存模型；缺失资源与无效源内容分别报告，不把资源加载失败解释成图已为空。
3. 外壳在运行时建立工具栏、查找、警告及渲染容器，调用外观与逻辑显示节点、连线和预览。源文本与渲染区域分开识别，新增界面不能被当作源节点或正文收集。
4. 沿用既定流程完成默认收起、尺寸测量、局部避让和初始视野适配，再接入编辑；实际节点和 SVG 连线继续同步更新。

运行时 ID 与源节点、边的标识协调，不因生成界面或预览而形成重复标识。源文本仍是唯一持久化图描述，派生索引与渲染结构不成为第二份可独立修改的数据源。

### 工具区域与画布的技术接入

工具区域由公共外壳程序生成，使用相对于页面视窗的界面定位，与图内容的平移缩放容器分开；图平移、缩放或节点避让时，工具位置与尺寸保持不变。左侧工具栏和右上方警告栏始终挂载并显示，没有关闭或收起状态；查找框独立维护显示状态，每次新文件会话或刷新默认关闭，通过右上入口打开、右端按钮关闭。样式沿用主题中的工具底色和边框色，分组按 S4，不照搬参考图的功能清单。

画布可以延伸到各浮置工具下方，但初始适配、居中定位与焦点跟随必须避开当前可见的工具覆盖范围。外壳测量左侧工具栏、右上方警告栏和打开时的查找框，技术上可先采用工具栏右侧、上方条带下缘以下的保守矩形；这只是视野计算区域，不将其画成另一块侧栏或顶部面板。查找框打开、关闭或警告内容改变高度时更新测量，关闭的查找框不占用遮挡范围。视野调整只沿用 L7 的平移与初始适配规则，不移动节点、不改变用户缩放，不在每次显隐时重新缩回全图。

工具区域事件由外壳接收并调用既定逻辑，不透传为下方画布的框选、拖拽或重复点击；新建入口仍按已有规则捕获旧焦点后再收尾。图标按钮保留可识别的名称与键盘接入，不依赖悬停提示，沿用 A3 无悬停反馈的规则。关闭查找只退出该输入界面，不关闭其他工具、不改写图内容或自动保存；其可见性不直接成为图对象的编辑焦点。工具界面与布局状态不写入图源文本。

查找框复用已有文本索引与节点／边筛选，结果计数按命中对象去重，不能因为一个节点多个字段命中而重复计为多个对象；通过上／下箭头定位，不生成可点击的结果列表。警告栏读取当前会话的诊断列表，空状态技术文案暂定“暂无警告”，有诊断时显示位置与原因；多条内容使用受限高度内的可滚动列表，不丢弃诊断、不转为瞬时提示。右上工具区将缩放滑块、比例、回原点和查找入口与警告内容一起布局，诊断仍保有可见区域；查找框位于整组下方，组内尺寸变化时重新测量，避免互相覆盖。

### 入口分发、快捷键与查找导航

左侧工具栏顶部按新建图、打开其他图、保存的顺序固定文件操作组，下方安排五种形状及线型入口。线工具提供贝塞尔、直角折线、直线选择；具体图标和间距由技术实现确定，选择后复用 L1 两阶段建边流程。普通节点点击仍用于焦点或已有手势，不因上一次线型选择残留而在普通模式误建边。

形状按钮在原生按钮取得焦点或旧对象失焦前捕获当前应用节点焦点，决定本次是换形还是新增。先完成必要的编辑收尾；换形目标仍存在时更新其形态，将节点编辑焦点交回同一节点，并按既定规则测量与局部避让；若目标因空标题收尾被删除，本次换形结束，不补建节点或恢复失效焦点。无节点焦点时调用通用新增规则；节点焦点、边焦点、批量选集不能混为一类。普通按钮点击造成的原生焦点变化不能让有焦点换形误走新增分支。

快捷键由外壳按当前图会话分发：Ctrl+Z／Cmd+Z 调用图级撤销，阻止同一次按键同时进入浏览器原生文本撤销；Delete 沿用整对象／选集删除。复制采用 Ctrl+D／Cmd+D 作为技术默认组合，直接执行已有的生成副本操作，不增加剪贴板复制／粘贴流程；有效批量节点选集是复制目标，可仅含一个节点。没有有效目标时不误复制旧对象，输入法组合过程按既有文本接纳规则处理。不存在撤销、复制、删除的按钮或菜单，也不把 Ctrl+Shift+Z／Cmd+Shift+Z 接入重做。

缩放比例以百分比显示，100% 对应图坐标比例 1；比例是当前滑块值的显示，不另增比例输入框或加减按钮。滑块调用统一视野变换，必须能表示当前初始适配得到的比例，不以可读性强制抬高下限。回原点沿用仅平移、不改变比例的规则；查找入口只打开并聚焦现有查找框。

查找保留按源文本对象顺序排列的命中 ID 序列与当前索引。输入或改变筛选先重算结果、清除旧的查找定位标记，不自动移动视野；只有激活上／下箭头才定位。技术默认下一项从首项开始、上一项从末项开始，后续循环切换；无结果时按钮不可执行定位。定位前重新检查对象是否存在，排除过期结果。筛选采用查找框内的节点、边两个紧凑选项，不添加第三种条件；数量和当前对象片段可显示，但不能点击片段直接跳转。箭头控件保留“上一个”“下一个”的可识别名称，不依赖悬停提示，也不通过全局上下方向键绕开按钮操作。

### 保存与文件会话

保存请求交给逻辑完成编辑收尾、有效模型校验与源文本序列化；外壳组合最小 HTML 文档结构、格式标识、当前版本的资源引用及有效源图。普通原位保存保留资源引用和正文图片引用，不复制公共程序，不序列化整份运行时 DOM，也不输出工具栏、输入控件、SVG 路径、公式预览或诊断文字。

新图先在内存中维护内容和所用公共资源版本，只有首次手动保存才请求目标文件位置；目标确定后，按实际路径生成指向该版本的相对资源引用，不能用示意目录提前替用户决定位置，也不借用旧图路径作为新图保存目标。已有图原位保存保留当前引用，不增加另存或异地副本流程，不擅自下载、复制图片或公共资源。

首次选择位置取消时保留内存草稿，不报告保存成功；完成写入并关闭写入流后才确认已保存。位置未定时，不为图创建临时文件或浏览器持久草稿，也不将原页面文件位置当作新图正文图片的资源基址；相对图片尚无法解析时沿用既定加载失败规则。目标确定后使用新图实际基址，保存成功后按既定磁盘变化规则刷新。任何写入异常都不得误报成功；若已经发生磁盘变化，强制刷新原则仍适用。

文件句柄、写入授权与磁盘变更检测衔接现有[文件写入草案](source-text.md#手动保存与文件写入方案)。资源就绪不代表写回权限已获得；先验证 Chrome 和 Codex，再按实际差异处理其他 Agent 宿主。本轮不指定新的保存后端，也不把兼容问题作为预先增加后台服务的理由。

任何当前图文件的磁盘更改仍触发强制刷新，包括本次手动保存；刷新废弃旧内存编辑、选集、展开状态、查找、视野和撤销历史。重新载入通过文件中的固定引用使用对应资源版本，旧会话的异步回调不得重新写入或恢复已废弃状态。

2026-10-15 文件流程实现补充：强制刷新以销毁并重建整个编辑会话实现，重新读取当前磁盘文件，只跨重建保留已授权的文件访问能力，不携带旧模型、草稿或历史；不要求用 `location.reload()` 重新导航浏览器。这样避免把重新导航后的授权恢复当作每次 Agent 改盘的必经步骤。资源版本仍按当前文件引用检查，不可因保留文件句柄而忽略版本变化或继续显示旧图。浏览器主动重新导航后的句柄恢复另行处理，权限缺失时明确报错并由用户重新选择文件。此接入调整仍须在 Chrome、Codex 中分别实测。

### 新建与同页替换的技术接入

新建整张图使用独立的图会话，初始化时复用既定新增节点默认值：标题“新节点”、空卡片文本和笔记、默认圆角矩形、默认收起，并按已有新节点规则聚焦。基于新图自身的无焦点视野计算初始位置，不继承旧图节点、选集、关系或视野参照，不创建旧图到新图的连线，也不复用旧文件句柄作为新图保存目标。提交新图切换后停止旧图的文件检测；新图尚未绑定文件时，不因旧图被改写而刷新这份新草稿。

文件选择和候选内容读取不直接提交图替换。目标图完成读取、资源准备并能够激活后，再切换当前会话；取消文件选择、读取失败或资源无法就绪时，不将当前图替换为伪造空图，也不误报已打开。局部源错误仍按已有规则展示有效部分与右上方警告。

同页替换时，目标图文件身份独立于页面最初打开的地址。原文件写回、相对图片解析及外部变更检测都以当前目标文件为准，不能继续使用上一个图的路径或句柄；公共资源按目标文件自己的版本引用加载，不因沿用当前页面而静默改用旧图版本。文件句柄、图资源基址及其与公共包的相对关系分别维护和验证，不能只根据文件名猜测所在目录。具体版本运行环境的切换与清理由实现验证，不在本轮编写代码。

提交替换时清理旧图的输入会话、选集、预览、诊断、查找、视野和撤销记录，并使旧异步回调失效；新图按既定载入规则恢复坐标、默认收起、局部避让与自动适配视野。不允许跨文件撤销或把旧资源请求结果写入新图。

保存入口按当前图是否已有目标文件分流：已有目标复用当前文件，未有目标的新图在本次手动保存中选择位置、生成相对引用并写入。选择保存目标的底层能力不等于提供“另存为”；不暴露另存按钮、菜单或快捷入口，保存失败不转而生成副本。

### Skill 与验证的接入边界

Skill 说明图文件只含源文本、必要文档结构与资源引用；Agent 修改图的有效节点、边、内容和布局属性，不将渲染结果写回，也不因普通改图改写公共包。路径失效、版本升级和普通内容编辑分别处理，不将所有图静默改为新版本。

已有只读字数及格式检查继续检查原始源文本，不需要先启动用户编辑器。公共资源检查与宿主运行检查另行验证，不把静态解析通过等同于离线运行或保存能力可用。相关脚本使用 TypeScript，本轮仅记录职责。
